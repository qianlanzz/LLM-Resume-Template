## 1. 可控性与可观测性（DFT 的第一性原理）

### 一句话定义

- **可控性（Controllability）**：从芯片外部输入引脚，能否把内部某个节点设置成想要的 0 或 1。分 **可控性-0（CC0）** 和 **可控性-1（CC1）**。
- **可观测性（Observability）**：内部某个节点的值能否传播到外部输出引脚被观察到。

### 面试怎么说

> 一个电路难测，无非两种原因：内部节点**设不了**（不可控），或者内部节点**看不出来**（不可观测）。
> - 深埋在逻辑里的节点，从输入到它可能要经过十几个门，要设成特定值需要同时满足很多条件 → 可控性差。
> - 节点的值要传到输出，必须一路上所有旁路门都处于「透明」状态 → 可观测性差。
>
> DFT 的所有手段，本质都是在**改善可控性和可观测性**：SCAN 通过把触发器串成链，让每个触发器的状态可以直接灌入和读出；测试点插入是在难控/难观节点上直接加控制或观测点；MBIST 是在存储器内部自建激励和比较器，绕开外部引脚的可控可观限制。

### 追问 Q：可控性和可观测性哪个更重要？

> 工程上更看重**可控性**。原因是：ATPG 的算法是「先激活故障，再传播到输出」。如果故障点可控，即使不可观测，也可以加观测点解决；但如果不可控，工具连故障都激活不了，只能加控制点。而且实测经验上，可控性问题往往和时钟/复位/使能信号的设计强相关，是 RTL 层面就必须解决的；观测性问题相对容易通过扫描链或压缩结构缓解。

### 追问 Q：怎么量化可控性/可观测性？

> 有几个经典度量：
> - **SCOAP**（Sandia Controllability/Observability Analysis Program）：给每个节点算 6 个值（CC0、CC1、CO、SC0、SC1、SO），组合逻辑按门的类型做组合计算，能快速给全电路打分。优点是快，缺点是不考虑重汇聚（reconvergent fanout）导致的悲观/乐观误差。
> - **COP**（Controllability Observability Procedure）：SCOAP 的改进版，用概率模型。
> - **实际工程**：现在很少手算 SCOAP，而是直接用 ATPG 工具跑一遍，看**哪些故障/区域被判成 AU（ATPG untestable）**、或者覆盖率报告里的低观测节点，再据此加测试点。这比理论计算更准确。（注意 AU 是**故障的类别**，不是节点的类别。）

### 追问 Q：什么叫重汇聚扇出？为什么它让电路变难测？

> 一个信号分叉成两条路径，经过不同逻辑后又汇合到同一个门，叫重汇聚扇出。问题是：为了让某条路径上的故障传播到输出，需要给旁路输入赋特定值；但这个赋值又会通过另一条路径影响同一个门，产生矛盾（conflict），导致故障无法传播。这是 ATPG 中「不可测故障」的主要来源之一，也是为什么纯概率方法（SCOAP）会偏离实际。

## 2. AD-HOC DFT vs 结构化 DFT

| | Ad-hoc（临时性）DFT | Structured（结构化）DFT |
|---|---|---|
| 做法 | 针对具体电路手工加测试逻辑 | 用统一方法学（SCAN/BIST/JTAG） |
| 例子 | 分频时钟、加测试 MUX、把内部点引到引脚 | Full scan、MBIST、边界扫描 |
| 优点 | 灵活、面积开销小 | 自动化程度高、覆盖率高、可复用、工具支持好 |
| 缺点 | 依赖经验、覆盖率难保证、不可复用 | 面积/时序开销、需要工具流 |
| 现状 | 作为补充手段 | **工业界主流** |

**面试一句话**：

> 现代数字芯片的 DFT 基本是「结构化 DFT 为主 + ad-hoc 手段补充」。比如时钟旁路、PLL bypass 这类就是典型 ad-hoc，而 SCAN 和 MBIST 是结构化的。面试里被问到 ad-hoc 不用展开，说明它是针对具体问题手工加的、难自动化即可。

## 3. SCAN 链结构（必须能白板画出来）

### 3.1 基本思想

**把电路里所有的触发器在测试模式下串成一个（或多个）移位寄存器，用外部引脚直接读写内部状态。**

### 3.2 扫描触发器（Scan Flip-Flop / SDFF）

```
                  +-----------+
   D  --+----------|           |
        |          |   DFF     |---- Q (功能输出)
        |   +--+   |           |
        +---|1 |---|D       Q  |
            |M |   |           |
   SI ----->|  |   |           |
            |0 |   |           |
            +--+   |           |
             ^     +-----------+
             |
          SE (Scan Enable)
```

- `SE = 0`（功能模式）：D 端进触发器，正常工作。
- `SE = 1`（扫描模式）：SI 端进触发器，形成移位链。

**DFF 到 SDFF 的代价**：增加一个 2:1 MUX，**触发器自身面积**增加约 **15%–30%**（不含布线，随工艺库不同有差异；注意这是"触发器面积"口径，不是全芯片面积）。时序上 MUX 在 D 路径上会增加一点延迟。

### 3.3 完整扫描链连接

```
  Scan In (SI) ──> [SDFF_1] ──> [SDFF_2] ──> [SDFF_3] ──> ... ──> [SDFF_n] ──> Scan Out (SO)
                     ^            ^            ^                      ^
                     |            |            |                      |
   Scan Enable (SE) ─┴────────────┴────────────┴──────────────────────┘
   Scan Clock (CLK) ─┴────────────┴────────────┴──────────────────────┘
```

**四条关键信号**：
1. **SI（Scan In）**：扫描数据输入，来自芯片引脚或前一条链的末级。
2. **SO（Scan Out）**：扫描数据输出，到芯片引脚，供 ATE 比较。
3. **SE（Scan Enable）**：模式选择，`1` = shift，`0` = capture。
4. **CLK**：扫描时钟，shift 时用 ATE 的低速时钟，capture 时用功能时钟脉冲。

### 3.4 一次扫描测试的完整过程

以链长 `N = 100`，需要 `P = 1000` 个 pattern 为例：

```
   一个 pattern 的时序：
   ┌─ Shift 阶段（N 个时钟周期）──┐┌ Capture ─┐
   CLK: ‾|_|‾|_|‾|_| ... ‾|_|‾|_|  ‾|_|  (1 pulse)
   SE : ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾___
   SI :  D[0] D[1] D[2] ... D[98] D[99]
   SO :  ...  ...  ...      ...   R[0] R[1] ... R[99]  (逐个移出)
                                      ↑ capture 结果开始移出

   ① Shift in：SE=1，N 个时钟沿把激励向量 D[0..N-1] 移进链
   ② Capture：SE=0，加 1 个（或 2 个）功能时钟脉冲，让组合逻辑结果
              被触发器捕获，此时触发器里存的是"响应"
   ③ Shift out：SE=1，再移 N 个周期，把响应 R[0..N-1] 移出到 SO，
              同时把下一个 pattern 的激励移进来（流水线复用，省时间）
   ④ ATE 比较 SO 输出与期望值，不一致即为 fail
```

**关键点（面试必答）**：

> 第 ③ 步和第 ① 步是**复用**的：移出当前 pattern 的响应时，正好把下一个 pattern 的激励移入。所以每个 pattern 的开销是 **N + capture 周期**，而不是 2N。
>
> 全部测试时间 ≈ `P × (N + C) / f_shift`，其中 `C` 是 capture 周期数（stuck-at 通常 1，transition 通常 2），`f_shift` 是移位时钟频率。
>
> 代入：`1000 × (100 + 1) / 50MHz ≈ 2.02 ms`。如果要测 100 万 pattern、链长 1000，就是 `10^6 × 1001 / 50M ≈ 20 秒`——**测试时间是 DFT 工程师最重要的成本指标之一**，因为 ATE 机时按秒计费。

### 3.5 为什么要分成多条短链？

> 测试时间近似的线性正比于链长 N。如果 1000 个触发器串成 1 条链，每个 pattern 要 1000 个周期；拆成 10 条链、每条 100 级，只要 100 个周期，**测试时间直接降 10 倍**。
>
> 代价是：每条链需要一个独立的 SO 引脚（SI 可以共用），需要更多的测试引脚。工程上的折中是：用较少的引脚配合**扫描压缩（on-chip compression）**技术，在芯片内部用解压器把少量输入引脚扩展成很多内部短链，再用压缩器把很多内部链的输出压缩到少量引脚。

### 3.6 多链带来的问题：跨时钟域（Lockup Latch）

**问题**：如果一条扫描链跨越两个时钟域（比如 clkA 和 clkB），移位时两个时钟的相位/延迟不确定。当前级是 clkB 域触发器、后级是 clkA 域触发器时，clkA 可能比 clkB 早半个周期到达，后级就把**还没稳定的新值**采走了，产生 hold 违例。

**解决**：在跨时钟域的两个触发器之间插入 **Lockup Latch（锁定锁存器）**：

```
   clkB 域                          clkA 域
  [SDFF] ──> [Lockup Latch] ──> [SDFF]
              (低电平透明的锁存器)
```

> Lockup latch 在时钟的半个周期内保持数据，相当于给跨域路径人为加了半个周期的延迟，保证后级采到的是稳定值。它是一个 latch，但仅用于 shift 阶段，capture 阶段不参与功能，所以不影响功能时序——**这是锁存器在 DFT 中被允许使用的标准例外**（面试常考）。

### 3.7 扫描链划分规则（面试加分项）

一个合格的 scan chain 划分要满足：

1. **同一链内尽量不跨时钟域**；必须跨时加 lockup latch。
2. **同一链内不混用上升沿/下降沿触发器**；必须混时也要加 lockup。
3. **避免链上有 X 源**：X 会在链上传播，污染后续所有触发的比较结果。所以链上要避开未初始化存储器输出、模拟 IP 输出、未约束的异步信号。
4. **物理相邻优先**：P&R 阶段做 **scan chain reordering**，按触发器的物理位置重排顺序，缩短布线、减小绕线拥塞。逻辑连接关系由工具自动调整，不影响功能。
5. **链长尽量均衡**：最长链决定整个测试时间（所有链并行移位），所以链长必须均衡。工具一般会自动 balance。

### 3.8 Full Scan vs Partial Scan

| | Full Scan | Partial Scan |
|---|---|---|
| 定义 | 所有触发器都进链 | 只把部分触发器进链 |
| 覆盖率 | 高（stuck-at 常 >99%） | 较低，但比无扫描好很多 |
| 面积/时序开销 | 大 | 小 |
| 选链依据 | —— | 按可测性贡献度选：优先选能打破反馈环、能提升可控可观的触发器 |
| 现状 | **主流** | 用于面积/时序极度敏感或旧设计改造 |

**面试答法**：

> 现在 ASIC 基本都用 full scan，因为综合工具能自动插链、面积开销在可接受范围（**触发器自身面积约 +15–30%**，占全芯片面积比例小得多），而覆盖率收益极大。Partial scan 出现在面积/时序极紧、或者遗产设计只允许局部修改的场景，选链时通常用「环打破（cycle breaking）」准则——选中能打破时序环的触发器，让剩余电路变成近似组合电路。

## 4. 移位/捕获详解与 At-Speed 测试

### 4.1 Stuck-at 测试（DC 测试）

- **Shift**：SE=1，慢速时钟（例如 10–50 MHz），把激励灌入。
- **Capture**：SE=0，给 **1 个**功能时钟脉冲，触发器捕获组合逻辑结果。
- **Shift out**：慢速移位读出。

特点：只用低频时钟，**不需要 at-speed**，因为 stuck-at 故障是静态的，只要逻辑值传播正确即可。

### 4.2 Transition Delay Fault（TDF）测试（AC 测试）

需要**在功能频率下**施加两个时钟脉冲，检查信号能否在规定时间内完成跳变。

**两种经典方法**：

| 方法 | 全称 | 激励来源（V2） | 时钟 | 特点 |
|---|---|---|---|---|
| **LOC** | Launch-On-Capture | 第一个脉冲把组合逻辑结果捕获成激励（broadside） | **2 个功能脉冲** | 工业主流；SE 可低速，易实现 |
| **LOS** | Launch-On-Shift | 最后一个 shift 沿把数据移一位作为激励（skewed-load） | **1 个 shift 沿 + 1 个 capture 沿** | 覆盖更高；但 SE 必须 at-speed 翻转 |

**面试怎么说**：

> LOC（也叫 broadside）用两个连续的功能时钟脉冲：第一个脉冲把组合逻辑的结果捕获到触发器里，作为新的激励（launch）；第二个脉冲捕获经过组合逻辑后的响应。**两个脉冲之间是一个完整的功能时钟周期**，所以测的是真实的功能路径延迟。SE 在 capture 期间保持恒定的低电平，不需要高频翻转，所以实现简单、是工业主流。
>
> LOS（也叫 skewed-load）把扫描链的最后一次移位当作 launch：移位使 V1 进入触发器，再移一位就得到 V2，然后用一个 capture 沿采结果。它的优势是 **ATPG 更容易生成激励——因为 V2 直接来自链上的下一位，不受组合逻辑可达性的限制**，所以能覆盖更多故障，理论上 TDF 覆盖率高于 LOC。
>
> ⚠️ **一个常见误解要澄清**：LOC 和 LOS 的 **launch→capture 间隔都是一个完整的功能时钟周期**，不是"LOS 只有半个周期"。两者真正的区别有两点：
> 1. **V2 的来源**：LOC 靠组合逻辑产生（受限），LOS 靠移位产生（不受限）。
> 2. **SE 的时序要求**：LOS 要求 SE 在**功能频率下**完成高→低翻转，而 SE 是高扇出大网络，做到 at-speed 极其困难——这才是 LOS 在工业界不如 LOC 普及的真正原因。
>
> 补充一个考点：LOC 有一个固有缺陷——如果某个故障的激活需要特定初值，而该初值无法通过组合逻辑在第一个脉冲前建立，这个故障就测不到（结构上不可测）。这就是为什么 TDF 覆盖率通常比 stuck-at 低几个百分点。

**顺带澄清脉冲数的说法**（速查卡里也提到，容易说错）：

> - **LOC**：TDF 需要 **2 个功能脉冲**（launch + capture）。
> - **LOS**：只有 **1 个额外的 capture 脉冲**，launch 是借用了最后一个 shift 沿。
>
> 所以"TDF 就是两个脉冲"这句话**只对 LOC 成立**。被追问时说清是哪种方案，是很明显的区分度。

### 4.3 OCC（On-Chip Clock Controller）

**为什么需要它**：

> Shift 阶段要用慢速 ATE 时钟（否则功耗和机台时序都撑不住），capture 阶段要用 PLL 出来的高速功能时钟（测真实延迟）。两种时钟要能平滑切换，切换时不能产生毛刺和亚稳态。
>
> OCC 就是干这个的：它内部是一个时钟 mux + 若干同步触发器，在 ATE 控制信号（scan enable / pulse enable）的指挥下，在正确的时刻把时钟源从 ATE 切到 PLL，并且只在 capture 窗口输出**指定数量**的脉冲，然后切回 ATE 时钟。脉冲数和脉冲宽度（例如 1 个周期、或 2 个周期）都是可配置的。

**追问 Q：OCC 内部为什么用触发器做同步？**

> 因为时钟切换发生在两个不同来源的时钟之间，如果不做同步，切换瞬间会产生窄脉冲（runt pulse），把触发器打到亚稳态或错误状态。标准做法是用时钟门控单元 + 同步器，在时钟低电平期间完成切换，保证输出无毛刺。

### 4.4 X 的处理

**X 是什么**：仿真中的未知值，来自未初始化寄存器、多驱动冲突、存储器未初始化、模拟 IP 输出、总线竞争。

**为什么头疼**：

> 在扫描链中，一个 X 会沿着链一路移出，污染所有经过的 SO 比较；在压缩结构中，一个 X 会被 XOR 压进多个输出通道，导致整个 pattern 的观测结果不可信（这就是所谓 X-blocking / X-masking 问题）。X 会导致：
> - 覆盖率虚低（工具不敢用带 X 的 pattern）
> - ATE 上出现假 fail
>
> 处理手段：**X-bounding**（在 X 源和扫描链之间插入 AND/OR 门，测试模式下强制成确定值）、**X-masking**（在压缩器里屏蔽掉含 X 的通道）、**测试点插入 / bypass 逻辑**（把未初始化存储器的输出在测试模式旁路掉）。这三个词能说出来就很够用了。

## 5. 扫描压缩（Scan Compression / On-Chip Compression）

**问题背景**：现代 SoC 有几百万触发器，即使分成 500 条链，每条链 4000 级，pattern 数 20000，测试时间就是 `20000 × 4001 / 50M ≈ 1.6 秒`，再乘上多颗芯片的测试，ATE 机时成本极高。而且芯片引脚有限，不可能给 500 条链都配 SO 引脚。

**解决方案**：在芯片内部加 **decompressor（解压器）** 和 **compactor（压缩器）**：

```
   ATE 引脚（少量，如 8 个 in / 8 个 out）
        │                              ▲
        ▼                              │
   ┌──────────┐   内部短链（几百条）┌──────────┐
   │Decompressor│──┬─[chain 1]─┐──│ Compactor │
   │  (XOR/    │  ├─[chain 2]─┤  │  (XOR tree│
   │   LFSR 网络)│  ├─[chain 3]─┤  │   / MISR) │
   └──────────┘    └─[...]─────┘  └──────────┘
```

- **Decompressor**：把少量引脚的输入扩展成几百条内部链的激励。常用实现是 XOR 网络（每个内部链 = 若干输入引脚的线性组合）、或 LFSR（线性反馈移位寄存器）加相位选择。这本质是**线性编码**：内部链的激励空间是引脚激励空间的线性子空间。
- **Compactor**：把几百条内部链的输出压缩成少量引脚输出。常用 XOR 树、MISR（多输入签名寄存器）。

**关键指标**：
- **压缩比（compression ratio）**：**没有唯一定义**，常见有三种口径——① 未压缩 pattern 数 / 压缩后 pattern 数；② 测试数据量之比；③ 内部链数 / 外部通道数。工业界常引用 **10×–100×**。
  面试时如果被追问，先说清你指的是哪一种口径，别把三种混着说。
- **固定模式（fixed / bypass mode）**：压缩逻辑本身也要能被测试，所以提供 bypass 模式，让外部引脚直接连内部链。
- **X-tolerance**：压缩结构对 X 的敏感度。XOR 压缩对 X 极不友好（一个 X 污染整组），所以现代压缩器都带 X-masking 或 X-blocking 逻辑。

**工具名与归属**（记住这些能显专业，也容易被抓错）：
- **Synopsys**：DFTMAX / DFTMAX Ultra（adaptive scan 压缩）
- **Siemens EDA（原 Mentor）**：Tessent Scan / TestKompress，其压缩技术叫 **EDT（Embedded Deterministic Test）**
- **Cadence**：Modus

⚠️ **别搞混**：**EDT 是 Siemens/Tessent TestKompress 的技术**，不是 Synopsys 的。Synopsys 对应的是 DFTMAX 的 adaptive scan。两者都是「片上压缩」，但叫法不能互换。

**面试追问 Q：压缩会不会降低故障覆盖率？**

> 会略微降低。因为压缩后工具生成 pattern 的自由度受限（内部链激励必须落在解压器能产生的线性空间里），有些故障变得不可测。所以有个指标叫 **compression-aware coverage**。实践中一般设定目标，比如未压缩 99.5%、压缩后 99.0% 可接受，或者同时生成一小部分非压缩 pattern 补覆盖率。

## 6. 故障模型（Fault Models）

### 6.1 Stuck-At Fault（SAF，固定故障）—— 最基础

**定义**：假设某一根信号线永久固定为逻辑 0（stuck-at-0，SA0）或逻辑 1（SA1）。

**面试怎么说**：

> Stuck-at 是抽象的**逻辑级**故障模型，不关心物理缺陷是什么。它对应很多真实缺陷：金属线断口悬空、栅氧击穿导致输入固定、对电源/地短路等。虽然模型粗糙，但实践证明确实能覆盖大量实际缺陷，所以是 ATPG 的默认模型。
>
> 每个节点有两个故障：SA0 和 SA1。N 个节点的电路理论上有 2N 个故障，但通过**故障等价（fault equivalence）**和**故障支配（fault dominance）**可以大幅压缩（fault collapsing），实际 ATPG 处理的故障数往往只有理论值的 1/3 到 1/2。

**故障等价与故障支配（高频考点，也是最容易说反的地方）**：

> - **等价故障**：两个故障在所有可能的输入向量下，输出响应完全相同，则互为等价，测一个就够。比如 2 输入 AND 门的 a/0、b/0、c/0 三者等价——都只在输入 `(1,1)` 时被检测到。
> - **支配关系（按"能否省掉"来记，最不容易错）**：
>   如果**检测 f1 的每一个向量都能检测 f2**（即 `T(f1) ⊆ T(f2)`），那么只要针对 f1 生成 pattern，**f2 就被免费覆盖了**，因此 **f2 可以从故障表里删掉**，只保留 f1。
>
> **用 AND 门验证一遍**（面试时就这么推，绝对没错）：
> ```
> 输入 (a,b)，输出 c = a AND b
>
> 【等价】a/0、b/0、c/0 的测试集完全相同，都是 {(1,1)}   ← 三者等价，只留 1 个
> 【支配】a/1 的测试集：只有 (0,1)          ← 小
>         b/1 的测试集：只有 (1,0)          ← 小
>         c/1 的测试集：(0,0),(0,1),(1,0)   ← 大，包含了上面两个
>
> 所以 T(a/1) ⊆ T(c/1)、T(b/1) ⊆ T(c/1)，c/1 可以删掉。
> 只保留 a/1、b/1 —— 测了它们，c/1 一定被覆盖。
> 反过来不行：用 (0,0) 能测出 c/1，但测不出 a/1 和 b/1。所以"只留 c/1"会漏。
> ```
> AND 门压缩后的最小故障集是 **{a/0, a/1, b/1}** —— **3 个**。
>
> ⚠️ **注意别写成 4 个**：因为 a/0、b/0、c/0 三者等价，**只保留一个代表**就够了。如果你写成 `{a/0, b/0, a/1, b/1}`，就等于一边说"这三个等价、只需测一个"，一边又把它们保留了两次——**自相矛盾**。
>
> **通用结论**：n 输入 AND / OR / NAND / NOR 门，压缩后恰好是 **n+1 个故障**。2 输入 AND → 3 个。这个「n+1」是经典结论，**可以放心背**，面试官一听就知道你懂等价类。
>
> 用 3 个测试向量 `{(1,1), (0,1), (1,0)}` 就能覆盖全部 6 个原始故障（可以自己枚举验证）。
>
> ⚠️ **关于"支配（dominate）"这个词的方向**：不同教材对"谁支配谁"的措辞相反，面试时**不要纠结名词，直接讲"哪个能删、为什么能删"**，用上面的 AND 门例子把逻辑推一遍。这比背定义方向安全得多——因为定义方向说反了你可能没意识到，但例子推一遍不可能错。
>
> - **故障压缩（fault collapsing）**：利用等价和支配关系把故障列表缩小。分**结构压缩（structural）**和**功能压缩（functional）**，前者快、后者准（功能压缩能发现跨模块的等价，但计算量大）。

### 6.2 Transition Delay Fault（TDF，跳变延迟故障）

**定义**：某根线在应该跳变时**没有在时间窗内跳变**。分两类：
- **slow-to-rise（STR，慢升）**：应该 0→1 却变得太慢。
- **slow-to-fall（STF，慢降）**：应该 1→0 却变得太慢。

**面试怎么说**：

> TDF 是**故障模型上的简化**：它假设延迟缺陷集中在某一根线的驱动上，只检查「单根线的跳变够不够快」，把整条路径的延迟归结到一点。这比真正的 path delay fault 简单得多，但覆盖率高、pattern 数可控，是工业界 AC 测试的主流模型。
>
> 它需要 **at-speed** 测试：用两个功能时钟脉冲，第一个沿建立初值（launch），第二个沿捕获结果，两个沿之间的时间就是一个功能周期。


**追问 Q：TDF 的覆盖率为什么通常低于 stuck-at？**

> 三个原因：
> 1. **需要建立正确的跳变**：故障激活要求节点在 launch 沿之前有确定的初值，且该初值能在一个周期内建立。有些节点在扫描结构下无法建立所需初值（例如需要两个相反约束同时成立），成为 structurally untestable。
> 2. **需要 at-speed 时序路径可用**：有些路径经过不同时钟域、或经过 OCC 不支持的组合，无法在功能频率下 launch/capture。
> 3. **X 的影响更严重**：AC 测试里未初始化存储器等 X 源在 capture 窗口出现，直接导致大量 pattern 失效。
>
> 典型数字（**fault coverage 口径**）：stuck-at 通常 98%–99.5%+，TDF 通常 **90%–96%**（明显低于 stuck-at）。

### 6.3 其他故障模型（知道名词 + 一句话即可）

| 故障模型 | 含义 | 检测手段 |
|---|---|---|
| **Path Delay Fault（PDF）** | 某条完整路径的累积延迟超过周期 | 专门生成路径 pattern，pattern 数巨大，用于关键路径 |
| **Bridging Fault** | 两根线之间短路（AND-bridging / OR-bridging） | 需要专门模型，用 **IDDQ**（静态电源电流）或电压对比 |
| **IDDQ / 静态电流** | 缺陷导致静态漏电流异常升高 | 测静态电源电流，慢但灵敏度高；先进工艺下漏电大，能力下降 |
| **Transistor Stuck-Open / Stuck-Short** | 晶体管级开路/短路 | 需要晶体管级 ATPG |
| **Cell-Aware Fault Model（CAFM）** | 基于标准单元版图提取的**真实内部缺陷**位置 | 现代先进工艺主流，覆盖率比 SAF 高很多，Tessent Cell-Aware 是代表 |
| **Small Delay Defect（SDD）** | 微小延迟缺陷，TDF 抓不到 | 用 timing-aware ATPG（长路径优先）或 faster-than-at-speed |
| **Soft Error / SEU** | 辐射导致翻转 | 靠 ECC、TMR、scrubbing 等容错手段 |

**加分回答**：被问到「stuck-at 100% 是不是就说明芯片没问题？」

> 不是。stuck-at 100% 只说明「按 stuck-at 模型抽象的故障都测到了」，但：
> 1. 物理缺陷有很多不表现为固定值，比如电阻性短路、栅氧漏电、微小延迟——这些 stuck-at 抓不到。
> 2. stuck-at 用的是零延迟模型，不检查时序。
> 3. 覆盖率的分母是**工具定义的"可测故障集合"**——分母里排除了大量 UU/TI/BL/RE（未使用/tie住/阻塞/冗余）这类"本来就不可能测"的故障。这些排除项本身可能掩盖真实风险，所以报告里的百分比必须结合分类计数一起看，不能只看一个数。
>
> 所以工业上要 stuck-at + TDF + bridging + cell-aware + IDDQ 多模型组合测，只看一个数字没意义。这也是为什么面试里我一般会问一句「这个覆盖率的分母是怎么定义的」。

### 6.4 故障覆盖率（必考，但**不要把公式背死**）

⚠️ **先说结论，这是本文最重要的一条提醒**：

> **"故障覆盖率"没有唯一公式，它取决于你用哪个工具、以及报告的哪个口径。** 面试时如果直接背一个 `DT/(total-UU)` 的公式，很可能和面试官手里的工具报告对不上，反而暴露你只是在背。
>
> **正确的答法是**：说清楚"覆盖率的分母是**可测故障集合**，而不同工具对'哪些算可测'的定义不同"，然后说明你会**先看报告里的分类计数再算**。这个回答比背公式安全得多，而且更显专业。

**故障分类（先分类，再谈比例）**：

| 类别 | 含义 |
|---|---|
| **DT** (Detected) | 已被 pattern 检测到 |
| **PT** (Possibly Detected) | 可能被检测到，但受 X 影响无法确定（仿真出现 X） |
| **AU** (ATPG Untestable) | ATPG 判定不可测（冗余逻辑、不可控时钟、黑盒等）——**注意：AU 留在分母里**，它属于"理论上可测但工具测不了" |
| **UD** (UNDetected) | 未检测到；**由 UC（UNControlled 不可控）+ UO（UNObserved 不可观测）组成**，即 `UD = UC + UO`（Tessent 报告用 UD，不用 "ND"） |
| **UU** (Unused) | 该故障对应的逻辑未被使用 |
| **TI** (Tied) | 被 tie 到常量（常 0 / 常 1） |
| **BL** (Blocked) | 被阻塞 |
| **RE** (Redundant) | 冗余逻辑，本质上不可测 |

**关键**：**UT（Untestable）= UU + TI + BL + RE**，是"非真实可测故障"的合并口径。

⚠️ **最容易记反的一点**：**UT 不是"未测试"**——"未测试/未检测"对应的是 **ND（Not Detected）**。这个命名坑在面试里很常见，务必按上表记牢。

**故障类别之间的代数关系（权威来源：Tessent Shell Reference Manual 表 3-21）**：

```
FU (Full)       = TE + UT                        ← 全部故障
TE (Testable)   = DT + PD + AU + UD              ← 可测故障
UT (Untestable) = UU + TI + BL + RE              ← 不可测故障
DT (Detected)   = DS + DI + DR                   ← 已检测
PD (Posdet)     = PU + PT                        ← 可能检测
```

这个关系是**工具手册里明确写着的**，记住它比记两个百分比有用——因为**分母是什么，完全由这个集合划分决定**。

**两个覆盖率指标（Tessent 报告同时给出）**：

```
DT_eff = DT + credit × PD          ← credit 默认 50%（见下）

                 DT_eff
Fault Coverage = ──────            ← 分母 = 全部故障
                   FU
                 DT_eff
Test  Coverage = ───────────       ← 分母剔除 UU/TI/BL/RE
                 FU − UT
```

⚠️ **AU（ATPG untestable）在 TE 里，因此两个分母中都保留**——这是最容易搞错的一点。AU 不是"不可测故障"，它是"理论上可测、但工具测不了"，所以不能从分母里扣掉。

⚠️ **分子的关键：possible-detection credit（默认 50%）**

> **Tessent 的覆盖率分子不是单纯的 `DT`，而是 `DT + credit × PD`，`credit` 默认 50%。**
>
> 依据：Tessent 的 `set_possible_credit` 命令 ——
> *"specifies the percentage of credit that the tool assigns **possible-detected faults** … when calculating the **test coverage, fault coverage, and ATPG effectiveness**. The default credit value for possible-detected faults is **50 percent**."*
>
> 其中 `PD = PU + PT`（possible-detected 故障）。**这就是为什么拿 `DS+DI` 直接去除会对不上、总是差一点点。**
>
> **完整写法**：
> ```
> DT_eff = DT + 0.5 × PD
> FC = DT_eff / FU
> TC = DT_eff / (FU − UT)
> ```
>
> **实例验证**（手册真实报告，两组都能逐位对上）：
> ```
> DT = 112635+10037 = 122672,  PD = 199+7 = 206,  UT = 10026
> DT_eff = 122672 + 0.5×206 = 122775
>
>   FU = 136996:  FC = 122775/136996 = 89.62% ✅   TC = 122775/126970 = 96.70% ✅
>   FU = 135789:  FC = 122775/135789 = 90.42% ✅   TC = 122775/126970 = 97.62% ✅
> ```
> **同一个 `DT_eff` 同时命中两组报告的 4 个百分比**——credit 机制就是这个"差一点点"的真正原因。
>
> **面试就照这个说**：
> **"覆盖率分母不同：fault coverage 相对全部 FU，test coverage 相对 `FU − UT`。分子是 `DT + credit × PD`，可能检测故障按 `set_possible_credit` 的比例折算，**默认 50%**。所以我核对报告会先把 PD 折一半，而不是直接拿 DS+DI 去除。"**
>
> 这个细节**很少有候选人知道**，能说出来是明显的加分项。

**用真实报告验证分母**（取手册里两份真实报告，**注意 PD 很小，所以用 DT 近似也能对上**）：

| 总故障 FU | DT | PU | PT | UU | TI | BL | RE | 报告 FC | 报告 TC |
|---|---|---|---|---|---|---|---|---|---|
| 59164 | 58240 | 6 | 0 | 123 | 219 | 50 | 142 | 98.44% | 99.33% |
| 2758 | 2525 | 0 | 0 | 4 | 12 | 0 | 21 | 91.55% | 92.80% |

（第一行 PU=6，看似 PD≠0，但 6 太小、被百分比取整吃掉了，所以 `DT` 和 `DT+PD` 算出来都是 98.44% / 99.33%。**这正是"分子差一点点看不出来"的原因**——选这两行只是为了验证**分母**。）

验算第一行（**建议自己按一遍计算器，比背公式有用**）：
- `58240 / 59164 = 98.4382% → 98.44%` ✅ Fault Coverage（**分母是全部故障 FU**）
- `58240 / (59164 − 123 − 219 − 50 − 142) = 58240 / 58630 = 99.3348% → 99.33%` ✅ Test Coverage（**分母扣掉 UT**）

验算第二行：`2525 / 2758 = 91.5518% → 91.55%` ✅；`2525 / (2758 − 4 − 12 − 0 − 21) = 2525 / 2721 = 92.7968% → 92.80%` ✅

**关键观察**：两行的 **TC 都比 FC 高**——因为 TC 的分母被扣小了。看到报告里哪个百分比更大，就知道它扣没扣分母。

> 💡 这个"两行数据能对得上"本身就是你能在面试里讲的东西：**"覆盖率不是一个数，是一组分类计数算出来的比值。"** 面试官如果报一个数，你可以反问口径，这是很自然的技术交流，不是抬杠。

**直觉理解**：

> **Fault coverage 是"相对全部故障"的覆盖率**，最保守——它把工具认为不可测的（AU）也算在分母里，所以偏低。
> **Test coverage 是"相对真实可测故障"的覆盖率**，把 unused / tied / blocked / redundant 这些"本来就不可能测的"从分母里剔除，所以偏高。

**经验值**（各家报告常见范围，用于大致判断是否正常）：
- Stuck-at：FC 通常 **98%–99.5%+**
- TDF：**90%–96%**（明显低于 stuck-at，原因见 **6.2 节**）

**追问 Q：AU 很多说明什么？**

> AU 是"可测但 ATPG 测不了"的集合，通常意味着**设计约束问题**，不是工具问题：
> - 不可控的时钟 / 复位
> - 黑盒（模拟 IP、未建模的存储器输出）
> - 跨时钟域路径
> - 组合环
>
> 所以 AU 多的时候应该回去查**设计的可测性**，而不是硬调 ATPG 参数。这也是面试里区分"会看报告"和"会跑报告"的分水岭。

**追问 Q：覆盖率上不去怎么排查？**

> 按优先级：
> 1. **看 AU 的分布**：集中在某几个模块 → 黑盒、不可控时钟/复位。解决：加 bypass、加测试点、把黑盒换成行为模型。
> 2. **看是否有 X 源污染**：用工具报告定位 X 源，加 X-bounding。
> 3. **看是否有 DRC 违反导致部分逻辑被排除**：跑一遍 scan rule check，修 latch、多驱动、时钟问题。
> 4. **看 pattern 是否收敛**：ATPG 的 abort limit 设太小会产生大量 ND。提高 effort level 或 abort limit 重跑。
> 5. **最后才考虑加测试点**：有面积和时序代价，是最后手段。

**追问 Q：怎么和面试官聊覆盖率不出错？**

> 一句话：**"我一般不问'覆盖率多少'，而是问'这是哪个口径的覆盖率，分母里排除了什么'。"**
> 因为同样是"99%"，一个报 FC、一个报 TC，可能差好几个百分点；分母含不含 AU 也差很多。能主动澄清口径，说明你真看过报告，而不是背了个数字。

## 7. ATPG（自动测试向量生成）

### 7.1 问题定义

> 给定一个门级网表和一个故障列表，生成一组输入向量（pattern），使得每个故障**至少被一个向量检测到**，且 pattern 数量尽量少。
>
> 「检测到一个故障」需要三个条件同时满足：
> 1. **激活（Activate / Excite）**：把故障点设成与故障值相反的值。测 SA0 就要让该节点为 1。
> 2. **传播（Propagate / Sensitize）**：把故障效应（与正常值的差异）沿一条路径传到某个可观测的输出或触发器。
> 3. **可观测（Observe）**：输出端能读到这个差异，且不与期望值冲突。

### 7.2 五值代数（D 代数，面试高频）

| 符号 | 含义 |
|---|---|
| `0` | 确定逻辑 0（正常/故障一致） |
| `1` | 确定逻辑 1 |
| `X` | 未知 / 无关（don't care） |
| `D` | 正常值为 1，故障值为 0（"1/0"） |
| `D'`（或 `D̄`） | 正常值为 0，故障值为 1（"0/1"） |

**面试怎么说**：

> ATPG 的核心是 D 代数。`D` 表示「正常电路该点应该是 1，但故障电路是 0」——这个差异就是我们可以追踪的「故障效应」。如果一条路径能把 `D` 一路传到输出，输出端就会出现与期望值不同的值，ATE 一比较就知道有故障。
>
> 传播规则类似布尔运算：`D AND 1 = D`、`D AND 0 = 0`（被屏蔽）、`D OR 0 = D`、`D OR 1 = 1`（被屏蔽）、`D XOR 1 = D'`。所以要让 `D` 穿过一个门，必须给门的其他输入赋**非控制值（non-controlling value）**——AND 门给 1、OR 门给 0。

### 7.3 ATPG 算法演进（能说出名字和思想即可）

| 算法 | 思想 |
|---|---|
| **D-Algorithm（Roth, 1966）** | 第一个系统化算法：在 D 代数上做「激活 + 传播 + 一致性检查」的搜索。缺点是遇到冲突时回溯效率低。 |
| **PODEM（Goel, 1981）** | Path-Oriented Decision Making：只在**原始输入**上做决策，而不是在所有内部节点上，避免大量无效决策，效率大幅提升。 |
| **FAN（Fujiwara, 1983）** | Fanout-Oriented：引入「头线（head line）」概念，把搜索限制在扇出点，减少回溯；并做**唯一敏化**和**多路回溯**。 |
| **SOCRATES / recursive learning** | 通过蕴含（implication）提前发现冲突，剪枝。 |
| **SAT-based ATPG** | 把电路转成 CNF，用现代 SAT 求解器（如 MiniSat、CaDiCaL）解。优点是对难测故障（尤其冗余识别）远强于传统算法；缺点是内存和时间开销大，工业界常做「混合」：大部分故障用传统算法快速解决，剩下 5% 难啃的交给 SAT。 |

**面试怎么说（要显得理解而不只是背名字）**：

> 传统算法和 SAT 的关系，有点像启发式搜索和精确求解。传统 D 算法/PODEM/FAN 是启发式的，速度快，但遇到重汇聚和需要长回溯的故障会 abort。SAT-based 把整个电路编码成布尔约束，用 CDCL 求解器求解，对判定「冗余故障」特别强，因为冗余等价于 UNSAT。工业界 ATPG 工具现在基本都是混合策略，先快速跑一遍，难测的故障再用 SAT 精解，这样兼顾速度和覆盖率。

### 7.4 ATPG 的约束与 DRC

跑 ATPG 之前必须先做 **scan rule check / DFT DRC**，否则生成的 pattern 在硅上无效。检查项包括：

- 时钟是否可被 ATE 控制并旁路 PLL
- 复位是否可控且 shift 时无效
- 扫描链上是否有 latch、多驱动、时钟域混乱
- 是否存在组合环（combinational loop）
- 是否有黑盒（black box）未定义
- 是否所有触发器都在链上
- 三态总线是否有冲突

**ATPG 常见约束（SDC-like）**：
```
set_dont_touch          # 不想被优化/改动的模块
add_cell_constraints    # 给黑盒或模拟 IP 的输出赋常量
add_pi_constraints      # 固定某些输入引脚
add_clocks / add_clock_groups  # 定义时钟域
set_false_path          # 跨时钟域路径
# 注意：下面这些命令是示意，各家工具拼写不同，实际以手册为准
# 例如 Tessent 用 set_atpg_limits / create_patterns -coverage_effort High
#      TetraMAX 用 set_atpg -effort / -abort_limit
```

### 7.6 ATPG 与功耗（进阶考点，说出来很加分）

> 扫描测试有两个功耗陷阱：
> 1. **Shift power**：移位时，所有触发器每个周期都在翻转（相邻两级数据不同就翻转），翻转率远高于功能模式。几百条链同时移位，瞬时功耗和 IR-drop 可能超过功能模式，导致测试时电压塌陷、良品被判 fail（这叫 **测试引起的良率损失，test-induced yield loss**）。
> 2. **Capture power**：capture 瞬间，组合逻辑大量节点同时跳变，是功耗峰值。
>
> 缓解手段：Low-Power ATPG（工具选项）、部分链移位（把移位分成几组错开）、提高 shift 时钟周期（降频移位）、加时钟门控、在 pattern 生成时限制翻转数。这也是为什么测试要分「shift 慢、capture 快」两种时钟。

## 8. JTAG / 边界扫描（IEEE 1149.1）

### 面试怎么说

> IEEE 1149.1（JTAG）是**板级互连测试**标准。核心是在每个芯片的 I/O 引脚上放一个**边界扫描单元（BCell）**，把它们串成一条**边界扫描寄存器（BSR）**。这样可以通过 TAP 引脚控制整个板子上所有芯片的 I/O 电平，检测 PCB 上的开路、短路、虚焊。
>
> **引脚数目要答准**：IEEE 1149.1 **必备的是 4 根**——**TCK、TMS、TDI、TDO**；**TRST 是可选的**（异步复位 TAP，很多设计提供但不强制）。另外 **IDCODE 寄存器理论上也是可选的**，虽然实际上几乎都会实现。答「5 根」会被追问。
>
> 关键结构是 **TAP 控制器**（16 状态机，由 TMS 驱动），以及几个必需的寄存器：
> - **BSR（Boundary Scan Register）**：边界扫描链
> - **Bypass Register**：1 位，用于把不参与测试的芯片旁路，缩短链长
> - **IR（Instruction Register）**：放指令，决定当前选哪个数据寄存器
> - **IDCODE Register**：芯片识别码

**TAP 状态机的关键状态**（能说 5 个就够）：`Test-Logic-Reset`、`Run-Test/Idle`、`Shift-DR`、`Capture-DR`、`Update-DR`、`Shift-IR`、`Capture-IR`、`Update-IR`。

**DFT 中 JTAG 的实际用途**：
1. 板级互连测试（原始目的）。
2. **作为 DFT 的访问接口**：把扫描链、MBIST 的控制信号接到 TAP 上，这样不用额外加测试引脚，通过 JTAG 就能控制 scan enable、启动 BIST、读 BIST 结果。工业上叫「**JTAG-based DFT access**」。
3. 多芯片/多核（IEEE 1500 是核级 wrapper 标准，IEEE 1687 IJTAG 是片上仪器访问标准，用来访问片上传感器、PLL 等）。
4. 调试（Debug）：接 CPU 的 debug port，做在线调试。

**追问 Q：JTAG 和 SCAN 的关系？**

> 两者经常一起用但目的不同。SCAN 是**芯片内部**的测试结构，目的是让 ATPG 覆盖内部逻辑故障；JTAG 是**板级/系统级**的访问标准，目的是板级互连测试和提供片上测试资源的访问通道。实践中，芯片内部的扫描链控制器（scan chain controller）通常挂在 TAP 上，ATE 通过 JTAG 协议向它下命令，再由它去驱动内部的 shift/capture。这样做的好处是省引脚，坏处是 JTAG 串行协议速度慢，对大规模 pattern 传输是瓶颈，所以大芯片往往还是保留专用测试引脚 + 少量 JTAG 复用。

## 9. 本章速记卡（面试前 10 分钟看）

- DFT 第一性原理：**可控性 + 可观测性**。SCAN 同时改善两者。
- SDFF = DFF + 2:1 MUX，**触发器自身面积** +15~30%。
- 四信号：**SI / SO / SE / CLK**。
- 一次 pattern：`shift in (N) → capture (1 或 2) → shift out (N，与下次 shift in 复用)`。
- 测试时间 ≈ `pattern数 × (链长 + capture周期) / shift频率`；**加链数降链长，直接降测试时间**。
- 跨时钟域扫描链要插 **lockup latch**（半个周期延迟）。
- Stuck-at 用 **1 个**捕获脉冲；TDF 的 **LOC 用 2 个**功能脉冲（LOS 是 shift 沿 + 1 个 capture 沿，别一概说「2 个」）。
- **OCC** 负责 shift 慢时钟 / capture 快脉冲的切换，无毛刺。
- **压缩**：Decompressor（XOR/LFSR）+ Compactor（XOR/MISR），压缩比 10–100×。
- D 代数五值：`0 / 1 / X / D / D'`；传播要满足**非控制值**。
- 算法：D-Algorithm → PODEM → FAN → SAT-based（现代混合）。
- 故障分类：**DT / PT / AU / UD(未检测) / UU / TI / BL / RE**；注意 **UT = 不可测（UU+TI+BL+RE）**，**不是「未测试」**，别被这个命名坑。
- **覆盖率没有唯一公式**：FC 分母是全部故障，TC 分母要扣除 UU/TI/BL/RE，**AU 两个分母里都保留**。先问口径，别背死公式。
- JTAG = 板级互连 + DFT 访问接口，TAP 16 状态机。
- X 是万恶之源：X-bounding / X-masking / 测试点。
