## 三条必须提前想清楚的事

### 1. 为什么软件工程背景投 DFT？（**第一必答题**）

简历 110 行里 DFT 内容占比很低，面试官一定会怀疑投递诚意。**必须主动解释，不要等他问。**

完整的推荐答法在 [10 第 0 节](10-DFT面试准备-简历项目逐条答辩.md) 和 [11 第四部分](11-DFT面试速查手册与策略.md)。核心逻辑三条：DFT 有大量自动化/数据工程工作 → 原理已系统补齐 → 调试方法论可迁移。

### 2. 你没有 DFT 项目经历，被直接问到怎么办？

**绝对不要编。** 标准答法：

> 我没有产线级的 DFT 项目经历。我是在准备阶段系统学习了数字电路、SCAN、ATPG、MBIST 的原理和完整流程，也调研了工具链。我的项目经历里最相关的是大批量任务调度、断点续跑、日志分析和指标监控——这些和 DFT 的 regression、覆盖率报告分析是同一类工程问题。

**诚实 + 展示方法论 + 明确短板**，比含糊其辞安全得多。

### 3. 数字一定要能说清口径

面试官对"看起来像背的"数字会追着问。这些必须先核实：

- Qwen3-Embedding-0.6B 的**实际输出维度**（你线上配的）
- 教辅项目的**抽检样本数**（支撑 95%→98% 那个结论）
- 九方智投的**具体参数**（30 秒 / 100 条 / 2000 条是否与实现一致）
- **时间线重叠**：教辅项目 2026.02 起 与 九方智投 2026.05–08 重叠，要有统一口径

## 资料准确性说明

本套 DFT 资料经过**两轮独立技术复核**，并对照 **Tessent™ Shell Reference Manual v2021.3**（Siemens EDA 官方手册）等一手资料逐条核验。

**12 章 Tessent 专题的所有技术细节都取自该手册原文**，包括：产品线定义（Ch 1）、context/mode 机制（Ch 6 Table 6-6）、862 条命令（Ch 3–6）、故障分类代数（Ch 3 Table 3-21）、DRC 规则（Ch 7）、TSDB 结构（Ch 12）。文中每个 dofile 示例、命令语法均已在手册中核对，**凡是手册里查不到的语法一律不写**。

修正的会在面试中被当场问穿的错误：

| 修正项 | 错误版本 | 正确版本 |
|---|---|---|
| MATS+ 复杂度 | 3N | **5N**（按操作次数求和，不按元素个数） |
| March C− 元素数 | 5 个 | **6 个**（10N 不变） |
| March C 序列 | `⇕(r0)` 放末尾 | `⇕(r0)` 插在**升序对与降序对之间** |
| March SS 覆盖 | 含 NPSF | **不含 NPSF**（NPSF 需 68N/96N 专用算法） |
| ISO 26262 | "LFSR = Latent Fault Self-Repair"（虚构） | **LFM（潜伏故障度量）**；LFSR = 线性反馈移位寄存器 |
| 覆盖率公式 | 单一公式 `DT/(total−UU)` | **`DT_eff = DT + credit×PD`（默认 50%，`set_possible_credit` 可调）**；`FC=DT_eff/FU`、`TC=DT_eff/(FU−UT)`。分类代数（表 3-21）：`FU=TE+UT`、`TE=DT+PD+AU+UD`、`UT=UU+TI+BL+RE`，**AU 属 TE、保留在分母** |
| UT 含义 | 未测试 | **不可测 = UU+TI+BL+RE**（"未检测"是 ND） |
| LOS 时序 | "两个沿只有半个周期" | LOC 与 LOS 的 launch→capture **都是一个完整功能周期** |
| 故障支配 | 方向说反 | 改为按**"能否省掉"**陈述 + AND 门举证 |
| AND 门压缩集 | `{a/0,b/0,a/1,b/1}`（4 个，自相矛盾） | **`{a/0,a/1,b/1}`（3 个 = n+1）**——等价类只留一个代表 |
| SDFF 面积 | 15–25%（多处不一致） | **触发器自身面积 +15–30%**，全库统一 |
| March SS 定性 | "覆盖最强"、"含 NPSF" | **不含 NPSF**；不能说"最强"（March AB 同为 22N） |
| AAB/EAB 归属 | 当成 AU 子类 | **属 UD**（`UD.AAB` / `UD.EAB`）；AU 子类是 BB/CC/PC/TC/FP |
| `insert_test_logic` 描述 | 写成 `set_test_logic` 的 | `insert_test_logic` = 插测试结构+stitch 扫描链；`set_test_logic` 才是控制 set/reset/clock |
| C 规则范围 | "C1–C27" | 实际 **19 条**（C1–C10/C16/C17/C19/C21–C26）；C27 不存在 |
| `read_procfile` 时序 | 放在 setup 模式 | **Mode: analysis**，必须在 `check_design_rules` 之后调用 |
| 11 章题量 | 标注"60 题" | **实为 75 题**，已修正 |
| 09 工具命令名 | `check_design` / `dft_drc` 张冠李戴 | `dft_drc` 属 **Synopsys DFT Compiler**；Tessent 用 `check_design_rules` |
| EDT 归属 | Synopsys | **Siemens/Tessent TestKompress** |
| JTAG 引脚 | 5 根 | **必备 4 根**（TCK/TMS/TDI/TDO），TRST 可选 |
| Tessent 归属 | Synopsys | **Siemens EDA**（原 Mentor） |
| `check_design_rules` 模式 | analysis | **setup**（它是进入 analysis 的那道门） |
| `write_patterns` 格式 | `-format STIL` | **`-stil`**（开关形式） |

⚠️ **注意**：软件/项目部分（10 的项目答辩、11 的简历风险）中的**业务数字和事实**（如 embedding 维度、抽检样本数、时间线）**必须由你本人核实**——这些只有你知道真实情况，资料里给的是提问方式和应答框架。
