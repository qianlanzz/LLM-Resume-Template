---

## 1. 为什么存储器要单独测？

**面试开场答法**：

> 因为存储器用扫描链测不了，或者说测了也没意义。
>
> 三个原因：
> 1. **结构不同**：SRAM 是密集的阵列结构，不是标准单元触发器，无法插入 SDFF，也就进不了扫描链。
> 2. **故障模型不同**：存储器的典型缺陷是单元间耦合、位线干扰、地址译码错误、读写干扰——这些是**阵列相关的故障模型**，用 stuck-at 模型描述不了。典型故障有：单元固定故障（SAF）、跳变故障（TF）、耦合故障（CF）、邻域图形敏感故障（NPSF）、地址译码故障（AF）。
> 3. **规模不同**：一个 SoC 里存储器面积占比可能 50%+，必须用专门的、规整的算法（March）去覆盖，同时存储器是规整结构，用算法测效率极高——反而比扫描链划算得多。
>
> 所以工业上做法是：**存储器用 MBIST（Memory BIST），逻辑用 SCAN + ATPG，两者互补**。

## 2. MBIST 架构

### 2.1 整体框图（要能画）

```
             ┌─────────────────────────────────────────┐
             │           BIST Controller               │
             │  ┌──────────┐  ┌──────────┐             │
   BIST_GO ──┼─>│ 地址生成器 │  │ 数据生成器 │            │
   BIST_DONE─┼──│ (Address │  │ (Data    │             │
   BIST_FAIL┼──│  Gen)    │  │  Gen)    │             │
             │  └────┬─────┘  └────┬─────┘             │
             │       │             │                    │
             │  ┌────▼─────────────▼────┐               │
             │  │   控制状态机 (FSM)     │               │
             │  │  按 March 元素序列执行  │               │
             │  └────┬─────────────┬────┘               │
             │       │             │                    │
             │  ┌────▼────┐   ┌────▼─────┐              │
             │  │期望数据  │   │ 比较器    │              │
             │  │寄存器    │──>│(Comparator)│──> FAIL     │
             │  └─────────┘   └────▲─────┘              │
             └──────┬──────────────┼────────────────────┘
                    │  addr/data   │ read data
              ┌─────▼──────────────┴─────┐
              │      MUX（BIST/功能）      │
              └─────┬────────────────────┘
                    │
              ┌─────▼─────┐
              │   SRAM    │
              │  阵列      │
              └───────────┘
```

**核心组件（面试逐个问）**：

| 组件 | 作用 |
|---|---|
| **地址生成器** | 产生遍历存储器的地址序列，支持升序/降序/列地址优先/行地址优先等遍历顺序 |
| **数据生成器** | 产生测试数据（全 0、全 1、棋盘格、行条纹、列条纹、walking 1/0 等背景图形） |
| **期望数据寄存器** | 记录本次读操作**期望**读到的值（由算法决定） |
| **比较器** | 把实际读出的数据和期望值比较，不一致就置 FAIL 标志 |
| **控制 FSM** | 按 March 元素序列（如 `⇕(w0)`、`⇑(r0,w1)`）逐步驱动地址/数据/读写信号 |
| **BIST/功能 MUX** | 测试模式下把存储器端口从功能逻辑切到 BIST 控制器 |

### 2.2 MBIST 的关键接口信号

```
BIST_GO      // 启动 BIST（通常由 JTAG 或测试引脚驱动）
BIST_DONE    // BIST 完成
BIST_FAIL    // 有故障（可只给一根线，也可给具体失败地址）
BIST_RUN     // 忙标志
CLK / RST    // 测试时钟和复位
```

进阶版本会输出 **failing address / failing data**，便于失效分析（FA）。工业界还有一种做法是只输出一个 pass/fail 信号（signature），面积省但 debug 能力差。

### 2.3 MBIST 的运行流程

```
① 进入测试模式，把 SRAM 端口切到 BIST 控制器
② 断言 BIST_GO
③ FSM 按 March 元素序列执行：对每个地址，施加写/读操作，
   比较读出值与期望值
④ 全部 March 元素执行完 → 断言 BIST_DONE
⑤ 读 BIST_FAIL：0 = pass，1 = fail
⑥ 退出测试模式，把 SRAM 端口还回功能逻辑
```

**面试追问 Q：MBIST 什么时候跑？**

> 三个时机：
> - **晶圆测试（Wafer Sort / CP）**：早期筛掉坏 die。
> - **最终测试（Final Test / FT）**：封装后完整测试。
> - **上电自检（Power-On Self-Test, POST）**：系统启动时跑，用于汽车电子、服务器这类要求高可靠性的场景——**这是"自测试"这个名字的由来**，BIST 的 B 就是 Built-In。
>
> 汽车电子按 **ISO 26262** 的功能安全要求，需要定时或在运行中做自检来满足 **潜伏故障度量（LFM, Latent Fault Metric）**，具体的实现手段就是周期性 MBIST / 上电 MBIST，配合 **Transparent MBIST**（见下节）在不破坏存储内容的前提下做测试——这是个高频进阶追问点。
>
> ⚠️ **术语别混**：**LFSR = Linear Feedback Shift Register（线性反馈移位寄存器）**，是电路结构，和"潜伏故障"没有任何关系。ISO 26262 里对应的是 **LFM（Latent Fault Metric）**。这两个缩写长得很像，说串了会被当场抓住。

### 2.4 Transparent MBIST（进阶，加分项）

**问题**：运行中做 BIST 会破坏存储器内容（要写测试图形），但系统正在用这块内存。

**做法**：
> 测试前先把被测存储单元的内容**读出来暂存**，然后写测试图形、读回比较，最后把原内容**写回**。这样对外表现为存储器内容不变，测试是"透明"的。代价是需要额外的暂存寄存器和一个额外的读-写回步骤，测试时间变长。适用于汽车、航天等要求在运行期间持续自检的场景。

## 3. March 算法（面试重灾区，必须能背几个）

### 3.1 March 算法的基本概念

**March 元素（March Element）的记法**：

```
⇕ (w0)        // ⇕ 表示地址遍历方向可任意（升序或降序）
⇑ (r0, w1)    // ⇑ 表示升序（↑，从低地址到高地址）
⇓ (r1, w0)    // ⇓ 表示降序（↓，从高地址到低地址）

符号含义：
  w0 = 写 0
  w1 = 写 1
  r0 = 读并期望 0
  r1 = 读并期望 1
  ↑ / ⇑ = 地址升序
  ↓ / ⇓ = 地址降序
  ⇕ = 方向无关
```

一个 March 元素后面的括号里可以有**多个操作**，它们对**同一个地址**依次执行。例如 `⇑(r0, w1)` 表示：从地址 0 到末地址，对每个地址先读（期望 0），再写 1。

### 3.2 常用 March 算法（背下来）

#### （1）MATS+（5N）

```
{⇕(w0); ⇑(r0, w1); ⇓(r1, w0)}
```

- 复杂度：**5N**。算一遍：`⇕(w0)` 是 1 次操作 × N，`⇑(r0,w1)` 是 2 次操作 × N，`⇓(r1,w0)` 是 2 次操作 × N，合计 `1 + 2 + 2 = 5N`。
- ⚠️ **高频算错点**：不要按"3 个元素就是 3N"去数——**复杂度按操作次数（w/r 的个数）算，不是按元素个数算**。这是面试官最爱用来筛人的一道口算题。
- 能测：SAF（固定故障）+ AF（地址译码故障）
- **不能测**：耦合故障（CF）、跳变故障（TF）。原因看它的结构——只有第一轮写 0，后续都是"读当前值、写反值"，没有制造"写后立刻检查跳变"的模式，也没有形成相邻单元之间的反向干扰组合。
- 用途：快速筛查、面积/时间极度受限的场景，一般不单独用于量产。
- 顺带：**MATS = 4N**（最后一轮只有 `⇓(r1)`，没有回写 0），比 MATS+ 少一次操作。

#### （2）March C−（10N，工业界最常用）

```
{⇕(w0);
 ⇑(r0, w1); ⇑(r1, w0);
 ⇓(r0, w1); ⇓(r1, w0);
 ⇕(r0)}
```

共 **6 个 March 元素**（不是 5 个——`⇕(w0)`、`⇑(r0,w1)`、`⇑(r1,w0)`、`⇓(r0,w1)`、`⇓(r1,w0)`、`⇕(r0)`），每个元素串行遍历所有地址。

计算：`1N + 2N + 2N + 2N + 2N + 1N = 10N` ✅

- 结构上可以这样理解：先全写 0 → **升序**做一轮"读 0 写 1 / 读 1 写 0" → **降序**做一轮同样的 → 最后全读一遍 0 收尾。
- 能测：SAF、TF（跳变故障）、CF（耦合故障，含 idempotent 和 inversion 两类）、部分 AF
- 工业界 SRAM 测试的标准选择，覆盖率和测试时间平衡最好

#### （3）March C（11N）

```
{⇕(w0);
 ⇑(r0, w1); ⇑(r1, w0);
 ⇕(r0);                        ← 中间插入一次全阵列读 0
 ⇓(r0, w1); ⇓(r1, w0);
 ⇕(r0)}
```

⚠️ **注意位置**：March C 相比 C− 多出来的那个 `⇕(r0)` 是插在**升序对和降序对之间**的，不是加在末尾。复杂度 `1+2+2+1+2+2+1 = 11N`。

> 记忆法：**C− 是 C 去掉了中间那次读**。所以看到 C− 时不要去找"末尾多了一步"，末尾的 `⇕(r0)` 两个算法都有。

#### （4）March SS（22N，覆盖强）

```
{⇕(w0);
 ⇑(r0,r0,w0,r0,w1); ⇑(r1,r1,w1,r1,w0);
 ⇓(r0,r0,w0,r0,w1); ⇓(r1,r1,w1,r1,w0);
 ⇕(r0)}
```

每个元素 5 次操作，共 6 个元素：`1 + 5 + 5 + 5 + 5 + 1 = 22N` ✅

- 能测：**所有静态简单 RAM 故障**——SAF、TF、RDF（读破坏）、DRDF、WDF（写破坏）、以及各类 CF（CFst/CFid/CFin/CFtr/CFdrd/CFwd），还有 AF。
- ⚠️ **不能测 NPSF（邻域图形敏感故障）**。这是一个常见误记：SS 的名字里有 "SS"（Simple Static），它覆盖的是**简单静态故障**这一类，而 NPSF 需要专门算法，复杂度高得多（ANPSF/PNPSF 约 68N，含 SNPSF 约 96N），或者靠棋盘/条纹类图形配合。
- 也没法说它是"最强"：March AB 同为 22N，March RAW 是 26N，NPSF 专用算法更高。准确说法是"**22N 级别里覆盖静态简单故障最完整的之一**"。

#### （5）March LR（14N）、March SR（14N）

- **March LR**：14N，比 C− 更强，能测某些**链接故障（linked faults）**。
- **March SR**：14N，针对**现实故障（realistic faults）**设计——即从版图提取的、更可能真实发生的缺陷组合。

（省时间只说这两个就够。避免临场冒出不确定的算法名——被追问出处会很尴尬。）

#### （6）Checkerboard（棋盘格）与 Walking 1/0

```
Checkerboard: 偶数地址写 0x55，奇数地址写 0xAA，然后全读；再交换重来。
               （0x55 = 0101_0101, 0xAA = 1010_1010）

Walking 1:    先把全阵列写 0，然后对每个地址 i：
              写 1 到 i → 读所有其他地址应为 0 → 读 i 应为 1 → 写 0 回 i
Walking 0:    反之
```

- **Walking 1/0** 复杂度 O(N²)，只用于小存储器的研究或特定诊断。
- **Checkerboard / 行条纹 / 列条纹** 用于检测**邻域图形敏感故障（NPSF）**和位线耦合。

### 3.3 复杂度怎么算（面试必算）

**题目**：一个 1024×32 的 SRAM，用 March C−（10N），移位时钟 / BIST 时钟 100 MHz，问 BIST 时间是多少？

**解答**：

> N = 1024 × 32 = 32,768 个存储单元（bit 数）。
> 但注意——MBIST 的一个"操作"通常是**一次字访问（word access）**，即 32 bit 一起读写。所以实际遍历次数是 `1024` 个字地址，不是 32768。
>
> 若按**字访问**计：`10 × 1024 = 10,240` 个时钟周期，`10240 / 100MHz = 102.4 μs`。
> 若按 **bit 数**计：`10 × 32768 = 327,680` 周期 = 3.28 ms。
>
> **所以面试时一定要先问清"N 是 bit 数还是 word 数"**——这个澄清本身就很加分。实际 MBIST 的一个 March 操作是**一次字访问**（32 bit 并行读写），所以真实执行时间按上面的 102.4 μs 算；但如果覆盖率/故障数按 bit-cell 统计，看到的 N 会是 32768。**两个口径都答得出，就说明你真理解了 March 的执行方式。**

### 3.4 March 算法为什么能覆盖那些故障（原理性解释，加分）

> March 算法的本质是**对每个地址施加"写-读-写"的规律性序列，并用不同的地址遍历方向制造相邻单元之间的干扰**。
>
> - **升序 + 降序**这对组合是关键：升序读能检测"低地址单元影响高地址单元"的耦合，降序读能检测反方向的耦合。
> - **每一轮都在读旧值（r）之后立刻写相反值（w）**：这是检测跳变故障（TF）的标准手法——TF 的定义就是"单元在发生 0→1 或 1→0 跳变后无法保持新值"，必须先写一个值、读它、再写反值、再读。
> - **不同背景图形（全 0/全 1/棋盘）**：用来检测与相邻单元逻辑值相关的耦合故障（CF）和图形敏感故障（NPSF）。
>
> 所以 March 元素看起来是死记的序列，其实每个符号都在针对某一类故障模型，换方向是制造耦合，读后写是制造跳变。

### 3.5 March 算法的选型权衡

| 算法 | 复杂度 | 覆盖范围 | 适用场景 |
|---|---|---|---|
| **MATS+** | **5N** | SAF + AF（**不含 CF/TF**） | 快速筛查、大容量缓存 |
| **March C−** | **10N** | SAF/TF/CF/AF | **工业主力** |
| March C | 11N | 略高于 C−（多一次读） | 同上 |
| March LR | 14N | + 链接故障 | 要求高的车规/服务器 |
| March SR | 14N | 针对 realistic fault | 先进工艺 |
| March SS | 22N | 全部**静态简单**故障（**不含 NPSF**） | 关键存储器、诊断 |

⚠️ 这张表里的数字要能**当场口算验证**。面试官很可能指着某一行问"为什么是 5N"——按"操作次数求和"答，不要按元素个数答。

**面试话术**：

> 选 March 算法本质是在**测试时间**和**故障覆盖率（DPPM）**之间做权衡。量产线上，测试时间直接换算成成本，所以 10N 的 March C− 是主流。车规、航天这类对 DPPM 极度敏感的场景会用 14N 的 LR 甚至 22N 的 SS。我面的这类岗位，实际工作中常见的是给一堆不同大小、不同位宽的存储器做 MBIST 配置，在满足覆盖率目标的前提下把总测试时间压到预算内——这本质上是个**资源分配 / 调度优化问题**，和我在软件里做任务调度和容量规划的思路是一致的。

（最后那句话把软件背景和 DFT 连起来了，面试加分。）

## 4. SRAM 测试原理补充

### 4.1 SRAM 的基本结构和故障来源

```
   ┌──────────────────────────────────────┐
   │  行译码器 (Row Decoder)                │
   │         │                             │
   │   ┌─────▼──────────────────────┐      │
   │   │  存储阵列 (Cell Array)       │      │
   │   │  ┌──┐┌──┐┌──┐    ┌──┐      │      │
   │   │  │C ││C ││C │ ...│C │      │      │
   │   │  └──┘└──┘└──┘    └──┘      │      │
   │   │   │    │    │       │      │      │
   │   │  ═╪════╪════╪═══════╪═ 位线  │      │
   │   └──────┬─────────────────────┘      │
   │          │                            │
   │   灵敏放大器 (Sense Amp)               │
   │          │                            │
   │   列译码器 (Column MUX)                │
   │          │                            │
   │      数据 I/O                          │
   └──────────────────────────────────────┘
```

**故障来源**：
- **存储单元故障**：单元内部的晶体管缺陷，表现为 SAF、TF、CF。
- **译码器故障**：地址译码错误导致访问到错误单元（AF，Address Decoder Fault）。典型表现是"两个地址访问同一个单元"或"某地址永远访问不到"。
- **位线/字线故障**：位线短路、字线开路导致的耦合或固定值。
- **邻域图形敏感故障（NPSF）**：某单元的读写结果依赖于相邻单元的图形。这是先进工艺（FinFET、小尺寸）中最麻烦的一类，因为单元间耦合随工艺缩小反而更强。

### 4.2 AF（地址译码故障）的四种类型

| 类型 | 表现 | 检测 |
|---|---|---|
| 某地址无法访问任何单元 | 该地址读到固定值或前一个值 | March 的地址遍历 + 唯一性检查 |
| 某单元无法被任何地址访问 | 单元内容无法读写 | March |
| 某地址访问多个单元 | 写入影响多个单元 | March C− 的升序/降序组合 |
| 某单元被多个地址访问 | 同上 | March C− |

### 4.3 冗余修复（Redundancy Repair）—— 面试加分

> 大容量 SRAM 通常带**冗余行/冗余列**。MBIST 检测到故障后，可以通过 **BISR（Built-In Self-Repair）** 逻辑，用熔丝（eFuse）或寄存器记录修复信息，把坏行/坏列替换成冗余行/列。这能显著提升良率——尤其在大容量存储器上，一个 bit 坏掉不必要报废整颗芯片。
>
> 从 DFT 角度看，BISR 是 MBIST 的自然延伸：BIST 负责**检测**，BISR 负责**修复**，两者合起来叫 **BIST/BISR**，是先进 SoC 的标配。

## 5. LBIST（Logic BIST）

**和 MBIST 对照记忆**：

| | MBIST | LBIST |
|---|---|---|
| 测什么 | 存储器阵列 | 随机逻辑 |
| 激励来源 | 确定性算法（March） | **伪随机**图形（PRPG，通常是 LFSR/CA） |
| 响应分析 | 逐次比较（有期望值） | **压缩签名**（MISR，最后比对签名） |
| 覆盖率 | 高（算法针对性强） | 中等（随机图形对难测故障无效） |
| 是否需要 ATE | 可完全自主（自带 BIST_GO/DONE） | 可自主，但通常仍需少量测试点 |
| 面积开销 | 中等 | 较大（LFSR + MISR + 控制） |
| 主要用途 | 所有 SoC 必备 | 汽车/航天/系统级自检；先进工艺下补充 |

**LBIST 的核心结构**：

```
  ┌──────────┐                   ┌──────────┐
  │   PRPG   │──> 被测逻辑 ──> │   MISR   │
  │ (LFSR)   │    (CUT)        │(签名寄存器)│
  └──────────┘                   └────┬─────┘
        ▲                             │
        │        控制 FSM              ▼
        └───────────────────────> 期望签名比对
                                   (Good Signature)
```

- **PRPG**（Pseudo-Random Pattern Generator）：用 LFSR 产生伪随机图形作为激励。本质是一个线性反馈移位寄存器，特征多项式决定序列周期。
- **MISR**（Multiple-Input Signature Register）：把响应逐拍压缩成一个签名（signature），最后和"good machine signature"比较。**注意：签名压缩不是简单比较，而是"压缩后比较"**，所以会有混叠（aliasing）——理论上两个不同响应可能产生相同签名，但概率为 2^-n（n = MISR 位宽），n 取 32 时概率可忽略。

**LBIST 的弱点（面试必答）**：

> 1. **随机图形覆盖不了难测故障**：比如需要长序列才能激活的故障、需要特定组合的冗余附近故障。解决方式：**加权随机（weighted random）**、**测试点插入**、**确定性种子注入（把少量 ATPG 生成的确定性向量塞进 LFSR 的 seed）**。这叫 **mixed-mode BIST**，是工业界的实际做法。
> 2. **X 问题**：LBIST 对 X 极度敏感，MISR 里一个 X 会污染整个签名。所以 LBIST 通常要求设计里所有 X 源都做 X-bounding，或使用 X-tolerant MISR。
> 3. **面积和功耗**：LFSR/MISR 加上控制逻辑，面积开销比 scan 大；同时随机图形翻转率高，功耗大。

**一句话总结**：

> LBIST 适合"没有 ATE 或 ATE 访问受限"的场景（系统级自检、汽车电子在线自检、航天），以及先进工艺下作为 scan 的补充。它不是用来取代 ATPG 的——**ATPG 的确定性图形覆盖率永远高于随机图形**。这也是个高频考点：问"为什么有 LBIST 还要 ATPG"，就答确定性 vs 随机性的覆盖差异。

## 6. DFT 完整流程与工具链

### 6.1 一个项目的 DFT 时间线

```
① 需求与规划阶段
   - 确定覆盖率目标（stuck-at / TDF / 存储器）
   - 确定测试引脚预算、ATE 机台能力、测试时间预算
   - 确定压缩方案、BIST 方案、JTAG 方案
   - 输出 DFT spec（DFT 架构文档）

② RTL 设计阶段
   - 参与 RTL review，检查可测性规则（时钟/复位可控制、无 latch、无组合环）
   - 插入可测性设计（时钟 mux、复位控制、测试模式信号）
   - 跑 RTL 级 DFT DRC（SpyGlass / DFT rules）

③ 综合后（网表阶段）—— DFT 主战场
   - 跑 scan rule check / DFT DRC，修所有违反
   - Scan chain insertion（插链），得到扫描网表
   - 插 MBIST/LBIST 控制器，做 memory BIST 的 wrapping 和共享
   - 跑 test mode STA（shift + capture 时序检查）
   - 生成 ATPG pattern（stuck-at → TDF → 其他模型）
   - 门级仿真验证 pattern（带 SDF 反标）

④ P&R 阶段
   - Scan chain reordering（按物理位置重排，缩短布线）
   - 时序收敛后重新生成 pattern（因为网表变了）
   - 检查 IR-drop / 功耗，必要时做 low-power ATPG

⑤ 流片后
   - ATE 转换（STIL → ATE 格式），bring-up
   - 分析 fail pattern，做良率学习（yield learning）
   - 用 failing pattern 反推物理缺陷，做失效分析（FA）

⑥ 量产
   - 监控 DPPM、测试时间、测试成本
   - 根据良率调整测试程序（test program）和测试覆盖
```

## 7. 本章速记卡（面试前 10 分钟看）

- 存储器为什么单独测：**进不了扫描链 + 故障模型不同（耦合/译码/图形敏感）**。
- MBIST 五件套：**地址生成器 / 数据生成器 / 期望数据寄存器 / 比较器 / 控制 FSM**。
- MBIST 信号：`BIST_GO`、`BIST_DONE`、`BIST_FAIL`。
- 三个测试时机：**CP 晶圆测试 / FT 最终测试 / POST 上电自检**。
- **Transparent MBIST**：读-存-测-写回，运行中不破坏内存内容，车规必备。
- March 记法：`⇕(w0)`、`⇑(r0,w1)`、`⇓(r1,w0)`；括号内对同一地址顺序执行。
- **复杂度按「操作次数」求和，不按元素个数**：MATS+ = **5N**、March C− = **10N**（6 个元素）、March C = 11N、SS = 22N。
- **March C− 是工业标准**（C = C− 加上中间那次全阵列读 0）。
- **MATS+ 不测耦合故障；March SS 不测 NPSF**（NPSF 要专门算法，68N/96N）。
- 复杂度算完要澄清 **N 是 bit 还是 word**。
- March 原理：**不同方向上制造相邻耦合 + 读后写制造跳变**。
- **ISO 26262 里是 LFM（潜伏故障度量），不是 LFSR**；LFSR = 线性反馈移位寄存器，别混。
- 工具归属陷阱：**Tessent 是 Siemens 的**（不是 Synopsys），**EDT 是 Tessent TestKompress 的**，Synopsys 的存储器 BIST 是 **STAR Memory System**。

- **BIST 检测 + BISR 修复 = 良率提升**（冗余行/列 + eFuse）。
- LBIST：**PRPG(LFSR) 激励 + MISR 签名压缩**；弱点是随机覆盖 + X 敏感；实际用 mixed-mode。
- 流程主线：**RTL 可测性 review → 综合 → scan insertion → test mode STA → ATPG → 门级仿真 → P&R 重排 → ATE bring-up**。
- 工具：TetraMAX / DFTMAX（Synopsys）、Tessent（Siemens，MBIST 事实标准）、Modus（Cadence）。
- 你的软件背景卖点：**Tcl/Python 自动化 + 大规模任务调度 + 日志分析 + 覆盖率看板**。
