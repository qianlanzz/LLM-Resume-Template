01　从一个坏门，理解整条测试链路

先想象：芯片已经制造出来，深处有一个 AND 门的输出坏了。你能给它输入什么，又从哪里看到错误？

芯片内部通常有大量触发器和组合逻辑，但外部引脚有限。正常功能输入只能间接改变内部状态，功能输出也不会直接显示每个寄存器里的值。即使系统能启动，某些制造缺陷也可能一直没有被触发。

可测试性设计（DFT）在设计阶段加入测试访问与控制结构，让外部设备或片上控制器能够施加激励、执行测试、观察响应。它帮助检测制造缺陷；它不能代替功能验证，也不是给芯片添加另一项用户功能。

RTL 与时序先看懂寄存器如何保存与更新数据。
SCAN 与 ATPG控制内部状态，计算能检出故障的向量。
MBIST 与 March按地址、数据和顺序检查存储阵列。
工具与 Debug理解输入、前置条件、报告和失败原因。

这套教程沿用对话中的学习顺序：电路结构 → 动态过程 → 故障检测 → 工程流程 → 动手实验。先用小电路把因果讲清，再把同样的思路放到大型设计和工具报告里。

读完时，应能自己画出扫描触发器和扫描链，解释 Shift/Capture，手算一个 ATPG 向量，执行 March C− 的读写顺序，并根据报告提出下一步排查方法。

02　RTL 不是软件：代码背后是一组同时工作的电路

RTL 是 Register Transfer Level，寄存器传输级。它描述数据在寄存器之间怎样流动，以及途中做哪些组合运算。下面这段代码对应一个 AND 门和一个 D 触发器：

always @(posedge clk)
    y <= a & b;

AND 门计算 D=a∧b，其输出会随输入变化；寄存器 Q=y 只在时钟上升沿采样 D，其他时间保存原值。这就是组合逻辑与时序逻辑最直观的区别。

波形实验：D 变化了，Q 会立刻跟着变吗？

选择 A=B=1，再推进到上升沿；随后改 B=0，观察 D 立即改变而 Q 等待下一上升沿。离散演示不模拟真实传播延迟、setup/hold 违例或亚稳态。

仿真、波形调试、综合各自回答什么？

环节实际做的事得到什么
RTL 仿真Testbench 给 DUT 时钟、复位和刺激；仿真器计算逻辑行为。输出、断言结果、VCD 等波形。
波形调试检查错误第一次出现在哪里、在什么时钟沿出现。能追溯到输入、状态或控制的根因。
逻辑综合优化逻辑，再按工艺库与面积/时序约束映射标准单元。门级网表及面积、时序等报告。

例如 y=(a&b)|(a&~b) 在二值布尔逻辑下等于 a。综合不必机械地保留两个 AND 和一个 OR；它可以消掉冗余，再按实际电气需求插缓冲或映射其他单元。RTL 仿真与综合后网表的用途不同，RTL 中的 X/Z 和真实硬件行为也不能简单等同。

调波形时建议按顺序查：时钟是否正常 → 复位是否正确释放 → 输入是否在预期时刻变化 → 寄存器是否在正确沿更新 → 输出是否符合期望。RTL 波形中的 X 表示未知，不是对晶体管级亚稳态的真实模拟。

03　数据不仅要对，还要在正确的时间到达

触发器是边沿采样，锁存器在使能窗口内透明。不要因为 Scan FF 前面有 MUX，就把它误认为“扫描模式下数据会直接穿过去”：它仍需要时钟有效沿才能更新。

Setup 要求数据在采样沿之前稳定足够久；Hold 要求采样沿之后继续稳定足够久。违例可能产生错误采样或亚稳态，不能保证只会采到某个确定的旧值或新值。

# 约定 skew = 捕获时钟到达时间 − 发射时钟到达时间
Setup: tCQ_max + tDATA_max + tSETUP ≤ T + skew
Hold : tCQ_min + tDATA_min ≥ tHOLD + skew

这是忽略时钟不确定度等因素的简化同频寄存器路径模型。正 skew 给 setup 更多时间，却让 hold 更难满足。Setup 检查的是最慢数据路径，hold 检查的是最快路径，不能把两者用同一个延迟值代入。

降频增加周期 T，可能缓解 setup 问题；hold 比较的是同一次发射/采样附近的最短时间关系，式子里没有 T，因此通常靠数据延迟或时钟树等措施处理，不能指望降频修好。

为什么 DFT 要重新查时序？

Shift 使用 SI 路径，Capture 使用功能 D 路径，时钟来源和控制条件也可能不同。移位频率较低不代表不需要 STA：hold 尤其容易受短数据路径和时钟偏斜影响；Capture 的 at-speed 路径还必须满足相应的高速约束。

跨时钟域的功能数据需要适当的同步方案：单 bit 控制常用同步触发器，多 bit 数据常用握手或异步 FIFO。STA 约束不能代替 CDC 验证，也不能把所有跨域路径一律设成 false path 而不考虑同步结构与数据一致性。

扫描链跨域是测试模式下的移位时序问题；功能 CDC 是不同功能时钟域之间传输数据的问题。二者都涉及时钟，但 Lockup Latch 不能替代功能数据的 CDC 同步方案。

04　故障要先被激活，再被看到

芯片外部输入称 PI，外部输出称 PO。可控性描述从测试入口把内部节点设为所需值的难易；可观测性描述内部差异能否传到可观察位置。前者决定能不能制造测试条件，后者决定能不能读到故障的影响。

假设节点 N 固定为 0，而你给的输入在好电路里也让 N=0，两边没有差异，故障没有被激活。即使好电路 N=1、坏电路 N=0，如果后面一个 OR 门的另一个输入恒为 1，两边输出都为 1，差异就被掩盖了。

设置条件控制输入与寄存器状态。
激活故障好电路与坏电路产生差异。
传播差异让旁路输入取非控制值。
观察响应从 PO 或扫描寄存器读出。

SCAN 给内部寄存器增加测试通道；控制/观测测试点改善特定逻辑锥的可测性；MBIST 用内部控制器为存储器产生地址、数据并比较响应。它们不消除全部难测情况，而是为测试提供更好的条件。

面试时可以说：“我先检查目标故障能否激活，再找传播到观察点的路径。如果状态装入困难，检查控制条件；如果差异被掩盖，检查旁路输入、X 源与观测结构。”这种解释比只背两个定义更完整。

05　普通 DFF 变成 Scan FF，究竟加了什么？

典型 Mux-D Scan FF 可以理解为一个 2:1 MUX 加一个 D 触发器。D 是功能数据，SI 是扫描数据，SE 是模式选择，Q 是寄存器输出。实际库单元还可能有异步复位、独立 SO 或其他控制端口。

always @(posedge clk)
    q <= se ? si : d;

SE=0 时选择 D，功能行为与普通触发器一致；SE=1 时选择 SI，按时钟沿接收扫描数据。SE 决定采哪条输入路径，不是异步地把输入直接复制到 Q。

增加 MUX、测试控制网络和扫描布线会有面积、时序与功耗代价。具体数值依赖库和设计；不能把“一个触发器的面积增幅”当成“整颗芯片的面积增幅”。

06　所有级一起更新，后一级接收前一级的旧值

将前一 Scan FF 的 Q 连到后一 Scan FF 的 SI，就形成扫描链。在 SE=1 时，四级链的下一状态是：

Q0⁺ = SI
Q1⁺ = Q0旧值
Q2⁺ = Q1旧值
Q3⁺ = Q2旧值；SO = Q3

这不是“一个时钟沿让新 SI 连续穿过四个触发器”。每次只能前进一级，四级链完整装入一个新状态需要四个沿。输入顺序与最终寄存器顺序相反，要先讲清链的方向。

沿输入 SI移出旧 SO沿后 Q0→Q3

从 0000 输入 1、0、1、1，逐次状态应为 1000 → 0100 → 1010 → 1101。当第四次移位完成时，最早输入的 1 已到末级 Q3。SO 当前显示 Q3，表中的“移出”记录采样沿前的 Q3，两者不要混淆。

多个链可以并行移位，因此装入时间通常由最长链决定。划分链时不能只追求平均长度，还要兼顾时钟域、触发器边沿类型、功耗和物理布线。

07　从装入状态，到捕获功能响应，再把结果读出来

SCAN 提供状态装入与读出通道。一次测试通常先 SE=1 装入激励，再 SE=0 让功能逻辑产生响应，并用相应捕获沿保存到寄存器，最后 SE=1 移出响应与期望值比较。

用对话里的两寄存器电路贯穿实验：q1⁺=a AND b，q2⁺=q1旧值 XOR b。扫描模式下则是 q1⁺=SI、q2⁺=q1旧值。

做一次完整手算

先 Shift 输入 0，再 Shift 输入 1，得到 q1=1、q2=0，也就是按 q2q1 排列的 01。设置 A=B=1 后 Capture：q1⁺=1；q2⁺=旧 q1 XOR 1=1 XOR 1=0。因此状态仍是 q2q1=01。

如果把 q2 错算成“刚更新的 q1”产生的值，有些输入恰好算出同样答案，仍不能证明理解了时序。可以从复位状态直接 Capture A=B=1：此时 q1⁺=1，q2⁺=0 XOR 1=1，得到 11。比较这两次实验就能看出旧状态的作用。

Shift Out 时，移出当前响应的同时通常可以移入下一组激励。这种复用省去了为每组 pattern 单独进行完整装入和卸载的额外开销，但首次装入和最后卸载仍需计入。

08　扫描链是通道，ATPG 决定给通道送什么数据

ATPG 是 Automatic Test Pattern Generation，自动测试向量生成。它读取设计、故障模型与测试约束，为目标故障求出能够检测它的模式。SCAN 改善内部状态的控制与观察；ATPG 利用这些条件寻找具体激励，二者分工不同。

手算例子：N=A∧B，Y=N∨C，检测 N stuck-at-0

第一步激活：坏电路 N 始终为 0，要产生差异，就让好电路 N=1。因此必须 A=B=1。第二步传播：如果 C=1，OR 门会把两边输出都强制为 1，差异被掩盖；令 C=0，Y 才能显示 N 的变化。答案就是 ABC=110。

反过来测 N stuck-at-1：好电路 N 必须为 0，A/B 至少有一个为 0；C 仍需为 0。此时好 Y=0、坏 Y=1。不是每个故障都只有唯一测试向量，ATPG 可以在多个解之间选择并压缩 pattern。

D 代数与实际求解

故障传播常用五值描述：0、1、X，以及 D=(好电路1，坏电路0)、D̄=(好电路0，坏电路1)。上面的 SA0 例子在 N 激活 D，再让 D 经过 OR 门传播到 Y。

复杂电路还有重汇聚和反馈约束：一个输入通过多条路径影响同一门，满足一条路径的赋值可能破坏另一条路径。ATPG 需要做逻辑推导、选择与回溯，不能靠“把故障点设成相反值”就保证测出。

D 算法、PODEM、FAN 是常见经典算法名称。入门阶段先能解释激活和传播；深入时再比较搜索的决策位置、回溯和蕴含方法，不要把算法名当作已经会用的证明。

09　逻辑值最后能对，也可能因为到得太晚而失效

Stuck-at 把故障抽象为节点固定为 0 或 1；transition-delay 把故障抽象为目标节点某个方向的跳变太慢。它们是测试用的故障模型，不是制造缺陷的逐项物理复制。

测慢上升通常先用 V1 将目标节点初始化为 0，再通过 V2 制造 0→1 跳变，并在规定时间后捕获。若给它很长时间，它最终也可能稳定为 1；高速 Capture 正是为了检查“是否在截止时间前到达”。

时序为示意、非等比例；Launch/Capture 标线与上升沿对齐。游标只表达教学阶段，不模拟真实门延迟。

LOC / BroadsideLOS / Skewed Load
Launch 从哪里来装载后第一个功能模式时钟沿。最后一个扫描移位沿。
第二个向量由功能逻辑更新寄存器产生。由最后一次移位产生，仍受移位关系约束。
SE 要求Launch 前已为 0，两个功能沿期间保持低。Launch 时为 1，之后及时切到 0，满足 Capture 条件。
脉冲计数两个功能脉冲：Launch + Capture。最后 Shift 沿 + 一个额外 Capture 沿。

两种经典方案的 Launch→Capture 间隔都是一个功能周期，不是 LOS 只有半周期。LOS 的优势在于 V2 的产生方式不同；不能据此保证它在任何设计中覆盖率都更高，也不能把 V1/V2 当成完全独立、任意的两组状态。

OCC（On-Chip Clock Controller）负责测试时钟控制，例如选择慢速移位与高速捕获时钟并输出规定脉冲。具体实现可能包含时钟门控、选择、同步与脉冲控制，必须避免毛刺和窄脉冲；图里的两个方波不能替代真实 OCC 协议和 STA 检查。

10　为什么最长链会决定 ATE 的移位时间？

假设多条链并行工作，长度为 500、700、1000、1800。一次完整装入需要按最长链的 1800 个沿安排，短链提前完成并不能让长链也完成。因此链均衡能减少等待，但还要考虑时钟域与物理约束。

总 FF 数 F、并行链数 M 且接近均衡时，最长长度近似 L=ceil(F/M)。P 个 pattern 流水化执行的 Shift 周期约为 (P+1)L：首次装入 L，之后复用 P−1 次装入/卸载，最后卸载 L。

Tshift ≈ (P+1) × L / fshift
Ttotal ≈ Tshift + P × Tcapture + Toverhead

改链数，观察时间如何变化

默认 L=1000，Shift 周期 1,001,000，在 20 MHz 下为 50.05 ms。把 M 改为 100，L=100，时间变为 5.005 ms。这个近似模型未算捕获、控制、压缩、链不均衡等开销，不是量产测试机的总机时预测。

若 Capture 使用功能频率，不能把所有周期都除以 fshift。应分别计算 Capture 时间，并考虑协议中的额外等待/切换；LOS 借用最后 Shift 沿 Launch，也不能机械套用 LOC 的脉冲数。

11　引脚少，内部链多：为什么还需要扫描压缩？

增加并行链能缩短每条链，但外部测试引脚与 ATE 通道有限。扫描压缩在片上用解压器将少量外部通道扩展到多条内部短链，再用响应压缩器将内部响应汇聚到少量输出通道。

ATE 输入较少外部数据通道。
解压器产生内部链所需的扫描数据。
内部扫描链并行装载与捕获。
响应压缩器汇聚后送到 ATE 比较。

压缩后 ATPG 必须考虑编码能力和相应约束。压缩比不等于测试时间按同样倍数下降；pattern 数、指定 bit 密度、X、链配置、覆盖目标都会影响实际收益。

X 为什么会影响响应？

未初始化存储器、黑盒模型、未约束输入等可能产生未知值。若响应经过 XOR 压缩，一个 X 会使某些压缩输出无法确定，从而影响该输出的比较能力。普通串行扫描里一个 X 不会自动让所有经过的位都变 X；要看实际传播和压缩结构。

X-bounding 在适当位置限制未知源影响，X-masking 在响应路径屏蔽未知比较位。两者都应保留足够的有效观测，不能为了消掉 X 就随意把功能信号全部设成常量。

Lockup Latch 处理的是什么？

跨时钟域或混合边沿的扫描链可能因偏斜产生移位 hold 问题。适当的 Lockup 元件为数据传递增加隔离时间窗口。是否需要、采用什么极性和位置，都要结合前后触发器的时钟关系；不是“跨域就随意加一个锁存器”。

物理实现中还可能重排扫描顺序，缩短布线并改善拥塞。重排后需要同步更新下游扫描信息与 pattern 使用条件，不能只改网表却沿用旧扫描链顺序。

12　工具不是黑盒：先说清输入、操作和输出

Tessent 是 Siemens EDA 的 DFT 工具体系。Shell 提供 Tcl 操作环境，Scan/ScanPro 与扫描结构相关，FastScan/TestKompress 与 ATPG 及压缩流程相关，MemoryBIST 与存储器测试结构相关。产品名称、功能与具体接口会随版本变化。

一次任务需要设计 RTL/网表、单元或存储器模型、顶层名称、时钟/复位/测试约束和流程配置。交付物可能包括插入后的设计、测试 setup/procedure、TSDB、扫描报告、故障报告和 pattern。真实项目往往分阶段执行，并不是永远“先综合，再一次性插完全部 DFT”。

Context 与 System Mode 别混为一谈

Context 决定当前处理哪类任务，例如扫描结构处理或扫描 pattern；System Mode 描述流程处于配置还是分析阶段。命令除了名字，还有限定 context、mode 和 prerequisites。应读安装版本的帮助，而不是只复制一段 Tcl。

14　一个 95%，不能独立解释测试质量

对话的基础例子是：目标故障 10,000 个，检测 9,500 个，按检测数/总数得 95%。这个算式适合入门，但真实报告必须先看故障模型、分类和统计口径。

原项目 08/12 章引用的 Tessent v2021.3 分类关系如下。不能把不同工具的同名类别混用，也不能把 AU 直接当成 UT 从分母扣除。

FU = TE + UT                    全部故障
TE = DT + PD + AU + UD           可测集合的分类
UT = UU + TI + BL + RE           不可测集合
DT_eff = DT + credit × PD
Fault coverage = DT_eff / FU
Test coverage  = DT_eff / (FU − UT)

DT 为已检测，PD 为可能检测，AU 为 ATPG 不可测分类，UD 为未检测；UT 是 UNTestable，不是“未测试”。在此口径中 AU 仍属于 TE。Possible-detection credit 在该版本资料中默认 50%，运行配置可能调整，核对报告时应读取实际设置。

同一组检测结果，为什么两个覆盖率不同？

默认有效检测数为 9000+0.5×200=9100。Fault coverage=91%；Test coverage=9100/9500≈95.79%。看上去第二个更高，只是分母不同，并不是又发现了更多故障。

遇到覆盖不达标，先分解未覆盖故障

大量 UC/UO 时查控制与观测条件；黑盒、约束相关分类要核对模型及约束；搜索放弃项才适合进一步评估资源限额和求解策略。AAB/EAB 在原项目引用的分类中属于 UD 子类，不能不加区分地说“全部 aborted 就是逻辑本身不可测”。

不要只为了把百分比抬高而删故障、改分母。报告中的定义、排除理由和测试适用条件需要一起说明。故障覆盖率也不是晶体管级“所有真实缺陷都被覆盖”的保证。

15　存储位不是普通 Scan FF，测试方法也不同

1024×8 SRAM 有 1024 个字地址、每个地址 8 bit，总容量 8192 bit。它通常由专用 memory macro 实现，内部包含存储单元、字线、位线、译码、读写驱动和感放等。不能把这些 bit 都当作可替换成 SDFF 的标准单元寄存器。

典型 6T SRAM 通过交叉耦合的存储结构保存值。写入时选择字线并由位线/写驱动施加数据；读取时选择字线，存储状态影响位线，外围读出电路判定数据。内部结构可能产生地址译码、转换、耦合与读写干扰等故障。

Memory Built-In Self-Test 在片内产生有规律的测试访问，并比较实际读回值与期望值。普通逻辑常用 SCAN+ATPG，嵌入式 SRAM 常用 MBIST，两者互补。

地址发生器决定当前地址与升/降序。
数据与 FSM生成背景值、读写操作和阶段。
存储器接口切换功能/测试访问，满足访问时序。
比较与状态检查读回，记录 DONE、FAIL 或诊断信息。

控制器既可以服务单块存储器，也可能通过复用/分组服务多块。能否同时测试要看接口兼容性、时钟、功耗和时间预算，不是连接到同一个控制器就自然同时测完。

MBIST 常用于晶圆或封装测试，也可在适用的系统中进行上电或周期性自检。破坏性 March 会覆盖原数据，在线测试还需考虑业务访问隔离、内容保存恢复或相应的透明测试方案。

16　看懂符号，比死背六行序列更重要

March 是按指定地址顺序，对每个地址执行一串读写操作。↑/↓ 是地址从低到高/从高到低，↕ 表示方向不限；w0/w1 是写入，r0/r1 是读取并比较期望值。

↑(r0,w1) 的意思是：地址 0 读0、写1，然后地址1读0、写1，以此类推。不能先读完整个阵列，再把整个阵列写1，那是另一种操作顺序。

阶段序列每地址操作数目的直观解释
M0↕(w0)1建立全0初始背景。
M1↑(r0,w1)2检查0，再制造0→1转换。
M2↑(r1,w0)2检查1，再制造1→0转换。
M3↓(r0,w1)2换访问顺序，施加另一方向的测试条件。
M4↓(r1,w0)2继续反向检查与转换。
M5↕(r0)1最后检查全0背景。

共有六个 March 元素，每地址操作数 1+2+2+2+2+1=10，所以是 10N，不是按元素个数算成 6N。下面用 4 地址×1 bit 演示 40 次基本操作，每一次真正执行一个读或写。

一读/写视作一步；无真实 SRAM 延迟。故障选项是明确的简化模型，实际 FAIL 来自期望/读回比较，不是直接勾选故障就置 FAIL。切换故障会从头开始。

为什么还要倒着访问？

耦合故障涉及 aggressor 与 victim：操作一个单元可能影响另一个。访问顺序会决定某个单元被修改时，相邻或相关单元处于什么数据背景、何时被读到。升序与降序提供不同条件，但逻辑地址相邻并不保证物理布局相邻。

March C− 对典型固定故障、转换故障及指定假设下的地址/耦合故障有检测能力；不能说它覆盖所有 SRAM 缺陷。具体覆盖范围还取决于 bit/word 组织、故障模型、数据背景和附加时序条件。

17　1024×8 的测试时间，为什么不直接乘 8192？

如果每个字访问同时操作 8 bit，March 的遍历对象就是 1024 个字地址，而不是 8192 次独立 bit 访问。March C− 的基本访问数为 10×1024=10240；假定一次读或写占一周期、100 MHz，理想时间为 102.4 μs。

这个模型已包含算法的 w0 初始化，但不含控制器启动、等待周期、SRAM 读延迟、访问流水线、额外背景、模式切换与收尾等开销。若一个操作需要多个周期，就要按实际访问协议计算。

算法选择是在覆盖目标与时间之间权衡

MATS+ 的序列 ↕(w0);↑(r0,w1);↓(r1,w0) 按操作计是5N。March C 比 C− 多一次位于升序对与降序对之间的全读0，因此是11N。复杂度能直接数出来，不应靠猜名字。

更长的 March 算法、棋盘格、条纹和保持/读干扰测试可能面向不同缺陷。不能单凭操作次数最多就称它“最强”，也不能只说“March 能测 NPSF”而不指定算法和背景。

测到故障以后，什么时候能修？

如果 SRAM 宏有冗余行/列和修复机制，故障地址与数据可用于诊断；BIRA（冗余分析）计算备用资源分配；BISR（内建自修复）应用修复配置。配置可能通过 eFuse/OTP 等机制保存，也可能在启动时装载。

MBIST 检测、BIRA 分析与 BISR 应用是不同环节。没有冗余资源、修复结构或可用分配方案时，不能因为“支持 MBIST”就说一定能自动修复。完成修复还需要重新测试验证。

18　逻辑也能自测，但签名相同不等于绝对无故障

LBIST 主要面向逻辑。典型结构用 PRPG 产生伪随机激励，经扫描链施加到逻辑，再用 MISR（多输入签名寄存器）压缩响应，最终与 golden signature 比较。

PRPG / LFSR逐步生成伪随机序列。
逻辑与 Scan执行测试并产生响应。
MISR连续累积压缩签名。
Golden 比较检查最终签名。

LFSR 是 Linear Feedback Shift Register，线性反馈移位寄存器。它不是“潜伏故障自修复”的缩写；功能安全里的 LFM 是另一种度量。具体反馈多项式、位序、种子决定序列，不是随意 XOR 几个位就一定得到合适的 PRPG。

响应签名不同说明测试发现了异常；相同仍可能漏检：激励未覆盖目标故障，或者不同响应序列压成相同签名，即 aliasing。LBIST 还需处理随机抗性故障、X 和切换功耗。

20　先讲因果，再讲命令；把学过和做过分开

对话中的教程旨在建立原理与工程流程的连接。自检时先用一两分钟独立回答，再展开参考答案。能够操作动画，不等于完成真实芯片测试；能够解释脚本，也不等于已经跑过量产 Tessent 流程。

1. SCAN 和 ATPG 各自解决什么？

SCAN 提供内部状态装入/读出的结构通道；ATPG 根据故障模型、网表和约束计算能激活并观测故障的 pattern。

2. 为什么下一级采前一级旧值？

同步边沿采样发生在寄存器输出更新之前。Verilog 中非阻塞赋值先按旧状态计算右侧，再更新左侧；一个沿不等于多级数据连续穿透。

3. A=B=1，却仍测不到 N stuck-at-0，为什么？

检查传播条件。Y=N∨C 时若 C=1，两边 Y 都为1，差异被掩盖。激活故障只是第一步，还要传播和观察。

4. LOC / LOS 的 Launch 分别来自哪里？

LOC 来自功能模式第一个沿；LOS 来自最后 Shift 沿。经典方案 Launch 到 Capture 间隔为一个功能周期。LOS 需要在这一窗口内完成 SE 切换。

5. 覆盖率不足，是否应该直接增加 pattern？

先看故障模型、分类、X 和约束，再根据根因选择措施。若故障无法激活/观察，仅增加 pattern 或搜索时间可能无效。

6. March C− 为什么是10N，N是什么？

六元素每地址操作数相加是10。N 应按算法实际遍历的位置定义；字接口可并行读写多 bit，字宽不意味着访问次数必然再乘同样倍数。

7. 没有真实 DFT 项目，怎样介绍目前能力？

说明实际学习与实验：“我理解 Scan/ATPG/MBIST 的基本机制，能手算测试例子、运行行为模型并分析典型报告。尚未做量产级 DFT；遇到具体工具任务，会先确认版本、输入、约束和前置条件，再运行和验证。”
