## 1. 组合逻辑与时序逻辑

### 一句话定义

- **组合逻辑（Combinational Logic）**：输出只由当前输入决定，与历史无关。没有存储、没有反馈回路。典型：与或非门、MUX、加法器、译码器、比较器。
- **时序逻辑（Sequential Logic）**：输出由当前输入**和历史状态**共同决定。一定含存储元件（触发器/锁存器）和时钟。典型：计数器、移位寄存器、状态机、FIFO。

### 面试怎么说

> 组合逻辑是纯函数 `Y = f(A, B)`，任何时刻输入变了输出立刻变化；时序逻辑是 `Y = f(A, B, 当前状态)`，状态的更新发生在时钟边沿。区分它们最直接的办法是看有没有「时钟沿采样」这个动作，以及有没有状态保持。

### 追问预案

**Q：为什么 DFT 要区分组合逻辑和时序逻辑？**

> 因为故障模型和测试方法不一样。SCAN 的本质是把时序电路在测试模式下「打散」成组合电路：把触发器串成扫描链，用扫描链直接把状态灌进去（shift in）、把内部状态读出来（shift out）。这样 ATPG 面对的就只剩触发器之间的纯组合逻辑，问题从「时序电路的状态空间搜索」降级成「组合电路的布尔可满足问题」，复杂度小几个数量级。

**Q：组合逻辑里常见的「毛刺（glitch/hazard）」是什么？对 DFT 有影响吗？**

> 毛刺是组合逻辑中由于不同路径延迟不一致，输出在稳定前出现的短暂错误值。在功能上靠时钟沿采样来规避（只要毛刺在建立时间前稳定即可）。对 DFT 有影响的地方是：ATPG 生成 pattern 时如果按「零延迟」模型仿真（zero-delay simulation），仿真结果和带 SDF 时序的真实硅片可能不一致，会出现 pattern 在仿真里 pass、在 ATE 上 fail 的情况。这时要么做时序仿真（timing simulation）核对，要么加约束把毛刺路径屏蔽掉。

**Q：你知道哪些组合逻辑的等价变换？**

> 常见的是代数化简（卡诺图、布尔代数）、布尔可满足性（SAT）化简、以及综合时的 don't-care 利用。DFT 里更相关的是**测试点插入（test point insertion）**：在难以控制/难以观测的节点上插入控制点（AND/OR 门强制某一值）或观测点（把内部节点引到扫描链或输出），本质是改变电路结构来提升可控性和可观测性——代价是面积、延迟和可能的时序影响。

## 2. 触发器（Flip-Flop）与锁存器（Latch）

### 必须能画出来的表

| 类型 | 触发方式 | 面积 | 时序分析 | DFT 友好度 |
|---|---|---|---|---|
| D 触发器（DFF） | 边沿触发（上升/下降沿） | 较大 | 简单，静态时序分析标准模型 | **好**，扫描链首选 |
| D 锁存器（Latch） | 电平触发（透明/保持） | 较小 | 复杂，可能出现 time borrowing | **差**，易产生 race / 难以串链 |
| 带扫描的触发器（Scan-FF / SDFF） | 边沿触发 + 测试模式 | 触发器自身面积约 +15–30% | 需分析测试模式时序 | 扫描链基本单元 |

### 面试怎么说

> 锁存器是电平敏感的，使能有效期间输出跟随输入（透明），使能无效时保持。触发器是边沿敏感的，只在时钟沿采样一次。触发器面积大但时序好分析；锁存器省面积但会让时序分析出现「时间借用」，而且对扫描链非常不友好，因为电平透明期间数据可以穿透，容易在扫描移位时产生竞争。

**追问 Q：既然锁存器对扫描不友好，为什么有些设计还在用？**

> 主要是面积和性能（time borrowing 可以在相邻级之间重新分配时序余量，帮助跑高频）。对这类设计，DFT 通常的处理方式是：要么在测试模式下把锁存器配置成可控/可观测（例如加 scan enable 强制其进入非透明模式），要么用 LSSD（Level-Sensitive Scan Design）等专门支持锁存器的扫描方法学。LSSD 用主从两个时钟分别控制、靠双时钟非重叠时序完成移位，代价是时钟树复杂。

### 追问 Q：锁存器导致的「race」在扫描链里具体是什么现象？

> 移位阶段，如果扫描链中间混入了透明锁存器，前一级的移位数据可能在同一个时钟周期内穿透锁存器继续往后传，导致部分触发器在本周期采到的不是上一级触发器的值，而是更靠前的值，链的移位关系被打乱，仿真和硅片结果不一致。典型表现是 scan chain 诊断报「链上有 X 个 shift 错误」或者 pattern 覆盖率异常低。

## 3. 有限状态机（FSM）

### 面试怎么说

> 状态机由状态寄存器 + 次态组合逻辑 + 输出组合逻辑三部分组成。按输出是否依赖输入分为 Moore 型（输出只由当前状态决定）和 Mealy 型（输出由当前状态和输入共同决定）。
>
> Moore 型的优点是输出稳定、毛刺少、时序好分析；缺点是响应慢一拍、状态数可能更多。Mealy 型的优点是响应快、状态数少；缺点是输出可能带毛刺，异步接口上要小心。
>
> 编码方式上，二进制编码（binary）省触发器；独热码（one-hot）每个状态一个触发器，译码逻辑简单、速度快、便于验证和调试，FPGA 和高速设计里常用。

### DFT 相关追问

**Q：状态机的 DFT 处理有什么特殊之处？**

> 状态机本质是一堆触发器加组合逻辑，所以 SCAN 一样适用——把状态触发器接入扫描链，就能直接灌入任意状态、读出当前状态。特殊之处有两点：
> 1. **不可达状态（unreachable state）**：有些编码组合是非法/不可达的，ATPG 有时会为这些状态生成 pattern（因为工具不知道它们不可达），需要加约束排除，否则覆盖率统计会失真或产生无意义 pattern。
> 2. **状态机自恢复逻辑**：正常设计里会有看门狗或默认转移把非法状态拉回来。这段逻辑在测试模式下可能干扰扫描，通常需要在测试模式屏蔽掉或者明确约束。

## 4. Verilog 基本语法（面试会挑几个点问）

### 4.1 阻塞赋值 `=` vs 非阻塞赋值 `<=`

**标准答案**：

> - `=` 是阻塞赋值，语句顺序执行，右边的表达式立刻求值并立刻赋值，后面的语句能看到更新后的值。用在**组合逻辑**（`always @(*)`）里。
> - `<=` 是非阻塞赋值，右边表达式在时刻开始时求值，赋值推迟到时刻结束时统一更新。用在**时序逻辑**（`always @(posedge clk)`）里。
>
> 一句话记法：**时序逻辑一律用 `<=`，组合逻辑一律用 `=`**。在时序逻辑里混用阻塞赋值会导致仿真与综合结果不一致（经典的 shift register 两拍变一拍问题）。

**经典例子（一定要能说出来）**：

```verilog
// 正确：两级移位寄存器，q2 比 q1 晚一拍
always @(posedge clk) begin
    q1 <= d;
    q2 <= q1;   // 这里 q1 是旧值
end

// 错误：混用阻塞赋值，综合/仿真结果可能变成一级
always @(posedge clk) begin
    q1 = d;
    q2 = q1;    // 这里 q1 已经是新值，q2 == d，少了一级
end
```

### 4.2 敏感列表

```verilog
always @(*)          // 组合逻辑推荐写法，自动推断敏感列表，避免漏信号导致综合出锁存器
always @(posedge clk)                    // 无异步复位
always @(posedge clk or negedge rst_n)   // 异步复位，低有效
```

**追问 Q：什么时候会综合出意外的锁存器（inferred latch）？**

> 组合逻辑 `always` 块里，如果某个分支没有给所有输出赋值，综合器为了让信号「保持原值」，就会推断出一个锁存器。这是设计里最常见的坑之一。解决办法：进入 always 块先给所有输出赋默认值，或者在 `if` 里写全 `else`。

### 4.3 阻塞/非阻塞之外常问的三个点

**Q：`wire` 和 `reg` 的区别？**

> `wire` 表示连线，必须被连续驱动（`assign` 或模块端口），不能存储；`reg` 是变量，可以在 `always`/`initial` 里被赋值，不一定综合成寄存器——组合 always 里的 `reg` 综合出来还是组合逻辑。在现代 Verilog/SystemVerilog 里推荐统一用 `logic`。

**Q：`parameter` 和 `localparam` 的区别？**

> `parameter` 可以在例化时被上层覆盖，用于可配置模块；`localparam` 不能在例化时覆盖，用于模块内部派生常量。

**Q：`initial` 块能综合吗？**

> 标准 Verilog 里 `initial` 用于仿真初始化，不可综合（FPGA 上部分工具支持上电初始化，ASIC 流程里不用）。ASIC 必须靠复位信号 `reset` 来初始化寄存器，这也是为什么 DFT 关心复位——扫描移位时需要保持复位释放，否则链上的值会被复位覆盖。

### 4.4 对 DFT 最关键的 RTL 常识

- **所有触发器必须能进扫描链**：RTL 里不能有纯行为级、无法映射到工艺库触发器的存储结构（比如大数组直接写 `reg [7:0] mem [0:255]` 而不走 SRAM 宏），否则 MBIST 和扫描链都没法处理。
- **时钟必须可控**：DFT 需要能旁路 PLL/DLL，用 ATE 直接给慢速时钟，所以 RTL 里时钟通常要做成 mux 结构（功能时钟 / 测试时钟）。问「DFT 对 RTL 的时钟有什么要求」就答这个。
- **必须有多路复用测试模式**：复位、时钟、扫描使能（scan enable）都要有测试模式控制。

## 5. 建立时间与保持时间（Setup / Hold）

### 一句话定义

- **建立时间（Tsetup）**：时钟有效沿到来**之前**，数据必须保持稳定的最短时间。
- **保持时间（Thold）**：时钟有效沿到来**之后**，数据必须继续保持稳定的最短时间。
- **违例后果**：违反建立时间 → 数据来不及到达，采到旧值（可用降频解决）；违反保持时间 → 新数据太快到达，把本周期该采的值冲掉（**降频无法解决**，必须改电路）。

### 面试怎么说

> 一次数据传输的时序检查可以写成：
>
> `Tclk_to_q + Tcomb_delay + Tsetup <= Tclk + Tskew`（建立时间检查，决定最高频率）
> `Tclk_to_q + Tcomb_delay >= Thold + Tskew`（保持时间检查，与频率无关）
>
> ⚠️ **符号约定要说清**：这里 `Tskew = T(捕获时钟到达) − T(发射时钟到达)`，正的 skew 有利于建立、不利于保持。不同教材的 skew 符号定义可能相反，**报公式前先声明你的约定**，否则和面试官对各不上会显得像背错了。
>
> 所以建立违例是「路径太慢」，可以通过降频、流水线、优化组合逻辑解决；保持违例是「路径太快」，降频没用，只能插入延迟单元（buffer）、改时钟树或修 RTL。

### 追问预案

**Q：DFT 里为什么要关心 setup/hold？**

> 因为 DFT 会引入新的工作模式：扫描移位模式（shift）和捕获模式（capture）。
> - **Shift 模式**：时钟走 ATE 的低频时钟，频率低，一般不关心建立时间；但移位路径是触发器的 scan-in → scan-out，这条路径不能有 setup/hold 违例，否则链上数据出错。
> - **Capture 模式**：要用一个（或几个）功能时钟把组合逻辑的结果捕获到触发器里，这个时刻必须满足功能电路的时序要求，否则捕获到错误值，pattern 在 ATE 上失效。
>
> 所以 CTS 之后要跑 **test mode STA**，专门检查 shift 和 capture 两种模式的 setup/hold。此外要检查 **clock skew**，因为 ATE 给的时钟往往抖动大、skew 大。

**Q：hold violation 为什么不能靠降频解决？**

> 保持检查的式子里没有时钟周期 Tclk 项。降频只加长了周期，只影响建立检查；保持检查比较的是「数据到达时间」和「同一时刻需要的保持窗口」，与周期无关。所以降频对 hold 违例无效。

**Q：CDC 和 setup/hold 的关系？**

> 跨时钟域路径因为两个时钟没有固定相位关系，静态时序分析无法给出确定约束，所以标准做法是：CDC 路径在 STA 里设成 false path（`set_false_path`）或 `set_clock_groups -asynchronous`，同时用同步器（两级触发器或握手/FIFO）保证功能正确性。如果不设 false path，工具会按最坏情况报一堆假的违例，且无法收敛。

## 6. 时钟、复位、CDC 与亚稳态

### 6.1 复位（Reset）

**面试怎么说**：

> 复位分同步复位和异步复位：
> - **同步复位**：`always @(posedge clk) if (!rst_n) ...`。优点是不会有时序问题、复位信号上的毛刺不会误触发；缺点是复位宽度必须大于一个时钟周期，且复位路径上会插入组合逻辑影响时序。
> - **异步复位**：`always @(posedge clk or negedge rst_n)`。优点是复位立刻生效、不依赖时钟、复位路径干净；缺点是有**复位释放（reset release）**的亚稳态风险。
>
> 工程上最常用的是「**异步复位、同步释放**」：异步复位保证即时性，释放时用两级触发器同步到时钟域，避免释放时刻落到时钟沿附近产生亚稳态。

**DFT 追问 Q：为什么扫描测试要控制复位？**

> 两个原因：
> 1. **Shift 阶段必须让复位保持无效**。如果复位一直有效，每个时钟沿都会把触发器清零，扫描链上的数据根本移不进去。
> 2. **复位本身也要能被测试**。复位树、复位同步器也是电路，也有 stuck-at 故障，需要 pattern 覆盖。所以通常做法是把复位做成 `功能复位 / 测试复位` 的 mux 或者直接由测试模式信号 gate 住，ATPG 生成 pattern 时能自由控制。
>
> 设计上常见的一个坑：RTL 里直接写 `if (!rst_n) q <= 0;` 而没有用可测试的复位 mux，会导致工具无法从复位端直接控制触发器，需要额外加测试点。

### 6.2 亚稳态（Metastability）

**一句话定义**：触发器的输入在时钟沿附近违反 setup/hold 时，输出可能在 0 和 1 之间的中间电平上停留一段时间，最终稳定到 0 或 1，这个不稳定状态叫亚稳态。

**面试怎么说**：

> 亚稳态不能消除，只能降低发生概率。衡量指标是 MTBF（平均无故障时间）：`MTBF = e^(t_r/τ) / (T0 × f_clk × f_data)`，其中 `t_r` 是留给亚稳态稳定的时间（即同步器级数带来的额外时间）。把同步器加到两级，MTBF 可以提升几个数量级，工程上足够。三级用于特别高可靠场景。

**标准同步器写法（要能背）**：

```verilog
// 两级同步器：把异步信号 sync 到 clk 域
reg sync_ff1, sync_ff2;
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        sync_ff1 <= 1'b0;
        sync_ff2 <= 1'b0;
    end else begin
        sync_ff1 <= async_signal;
        sync_ff2 <= sync_ff1;   // sync_ff2 才是稳定可用的值
    end
end
```

**追问 Q：两级同步器能同步多比特信号吗？**

> 不能。两级同步器只能同步单比特电平信号。多比特信号如果各比特独立打两拍，可能因为路径延迟不同而在同一时钟沿采到「新旧混合」的值（比如二进制计数器从 0111 变 1000，可能采到 1111）。多比特要用：
> - 格雷码（Gray code）：相邻值只变一位，最常用于异步 FIFO 的读写指针。
> - 握手（handshake）：req/ack 信号各自同步。
> - 异步 FIFO：双口 RAM + 格雷码指针。
> - 直接使用厂商提供的 CDC 单元（如 `set_max_delay -datapath_only` 约束的 MUX 结构）。

### 6.3 跨时钟域（CDC）

**面试怎么说**：

> CDC 的核心是「单比特用同步器，多比特用格雷码或异步 FIFO，绝不能靠单纯的时序约束来保证功能」。验证上有专门的 CDC 检查工具（SpyGlass CDC、Questa CDC、VC CDC），检查内容包含：缺少同步器、多比特聚合、复位跨域、时钟门控跨域等。

**DFT 追问 Q：CDC 路径对 ATPG 有什么影响？**

> 影响在故障覆盖率统计上。跨时钟域的组合路径在 ATPG 工具看来是「有时钟域交叉的组合逻辑」，工具可能无法生成有效 pattern 去激活/传播，这些故障会被报告成 untestable 或 ATPG-untestable，拉低覆盖率。处理方式：一般在 ATPG 的约束文件里明确标注跨时钟域路径为 false path / 不可测，统计覆盖率时扣除这部分，避免盲目追覆盖率做无用功。

**Q：亚稳态对 SCAN 测试有影响吗？**

> 有，主要体现在捕获阶段。如果捕获时钟来自 PLL 分频、相位关系不确定，或者 scan enable / 时钟之间有竞争，捕获时刻可能落在亚稳态窗口。所以 DFT 的普遍做法是：capture 阶段使用 ATE 提供的、和 shift 同源的稳定时钟脉冲（pulse），并通过 test mode 直接旁路 PLL，让时钟关系完全确定。这也是为什么 DFT 要求「时钟可绕过 PLL」。

## 7. RTL 仿真、波形调试与逻辑综合

### 7.1 RTL 仿真流程

**面试怎么说**：

> 典型流程是：写 testbench → 用仿真器（VCS / Xcelium / Questa / Verilator）编译 + 运行 → 产生 FSDB/VCD 波形 → 用 Verdi / DVE / SimVision 看波形调试。
>
> - **VCD**：文本格式，体积大，通用性好，`$dumpfile`/`$dumpvars` 生成。
> - **FSDB**：二进制格式，体积小、支持压缩，Verdi 原生支持，工业界主流。
>
> Testbench 里常用 `$display`、`$monitor`、`$assert`（SystemVerilog assertion）做自动检查，比人眼看波形效率高得多。

**Q：仿真器有哪些？**

> 主流三家是 Synopsys VCS、Cadence Xcelium（原 Incisive）、Siemens Questa（原 ModelSim）。开源有 Verilator（只支持可综合子集，速度快）、Icarus Verilog、cocotb（Python testbench）。DFT 领域还常用**门级仿真**，即在综合后的网表上带 SDF 反标时序仿真，验证 pattern 在真实时序下有效。

### 7.2 波形调试（面试常问「你平时怎么 debug」）

> 分三层：
> 1. **先看现象**：仿真报错在哪一行、哪个信号是 X 或 Z。X 通常来自未初始化寄存器、多驱动、或复位没接好。
> 2. **再定位边界**：从报错点往上追，找到第一个 X 出现的时刻，看它是被谁驱动的（Verdi 的 trace driver 功能）。
> 3. **最后判断类型**：是 RTL 逻辑写错、时序违例、还是 testbench 激励问题。
>
> 对 DFT 的 pattern 调试：DFT 工具（TetraMAX / Modus / Tessent）会输出 failing pattern 和 failing cycle，把它和仿真波形对齐，就能定位是哪一级扫描单元、哪个时钟沿出问题。这类问题我处理起来比较熟——本质和我做软件时的日志定位是同一套方法：先确定失败的最小复现单元，再逐层排除。

**DFT 场景的高频故障类型**（能说出来显得不是纯背的）：

| 现象 | 常见原因 |
|---|---|
| 整条 scan chain 全错 | 时钟没接对、scan enable 反相、链首尾接反 |
| 链上固定某几级错 | 该级触发器是 latch、或链上有 X 源 |
| 部分 pattern fail、部分 pass | 捕获阶段时序问题（hold 违例、时钟脉冲太窄） |
| 覆盖率上不去 | 不可控时钟/复位、黑盒、跨时钟域路径、模拟 IP |
| 仿真 pass、ATE fail | 零延迟仿真与实际时序不符、测试机时序设置（TDS）不对、电源噪声 |

### 7.3 逻辑综合（Synthesis）基本流程

**面试怎么说**：

> 输入是 RTL + 工艺库（.db/.lib）+ 约束（SDC：时钟、input/output delay、false path、multicycle path），经过三步——**翻译（translate）→ 逻辑优化（optimize）→ 映射（map）**——输出门级网表（.v）和时序报告（.sdf/.rpt）。工具主流是 Synopsys Design Compiler / Fusion Compiler、Cadence Genus。
>
> 综合产出的网表是 DFT 的主要工作对象：DFT 要在网表上做扫描链插入（scan insertion）、插入 BIST 逻辑、生成 pattern。所以有「**综合 → DFT → 布局布线（P&R）**」这个顺序，也有把 scan insertion 放在综合工具里一起做的流程（DC 的 `insert_dft` / `compile_ultra -scan`）。

**Q：为什么 DFT 一般插在综合之后、P&R 之前？**

> 因为这时候电路规模是门级的，工具能精确算出扫描链的时序和面积开销；同时 P&R 还需要知道 scan chain 的连接关系来布局，Scan chain reordering（链重排）会在 P&R 阶段根据物理位置调整触发器顺序以减小布线长度。如果太晚做，时序会很难收敛；太早做（RTL 阶段），工具无法准确估算。

**Q：综合会改变故障覆盖率吗？**

> 会。综合过程中的逻辑优化（常量传播、无用逻辑删除、等价变换）会改变故障集合本身——有些故障被优化掉了（redundant fault），有些新增了。所以 DFT 的实际流程里，ATPG 是在综合后的网表上跑的，覆盖率也是以那个网表为基准统计。此外 scan insertion 之后网表还会变，需要在插链后的网表上再跑一次 ATPG。

**Q：DFT 会引入哪些设计改动？**

> - 触发器替换成带扫描的触发器（SDFF），**触发器自身面积**增加约 15–30%（占全芯片面积的比例要小得多）。
> - 增加扫描链布线，需要额外的 scan enable / scan clock 网络。
> - 插入测试模式控制逻辑：时钟 mux、复位 mux、scan enable 生成。
> - 插入 BIST 控制器（MBIST/LBIST）和 OCC（On-Chip Clock Controller）。
> - 增加测试引脚或复用功能引脚（复用 JTAG 的 TAP）。
> 这些都会影响面积、功耗、时序，需要在项目早期就和设计、后端一起评估——这也是 DFT 工程师要参与 RTL review 的原因。

## 8. 本章速记卡（面试前 10 分钟看）

- 组合逻辑无记忆，时序逻辑有记忆且由时钟沿更新。
- 阻塞赋值 `=` 配组合 always，非阻塞赋值 `<=` 配时序 always。
- 组合 always 分支不全 → 综合出 latch。
- Setup 违例可降频解决，Hold 违例不能。
- 时序检查两式：`Tco + Tcomb + Tsetup ≤ Tclk + Tskew`；`Tco + Tcomb ≥ Thold + Tskew`。
- 异步复位同步释放；两级同步器只同步单比特；多比特用格雷码/异步 FIFO。
- 亚稳态不能消除，只降概率；MTBF 随同步级数指数增长。
- 仿真波形：VCS/Xcelium/Questa + FSDB + Verdi。
- 综合三步：translate → optimize → map；DFT 通常在综合后、P&R 前插入。
- DFT 关心的 RTL 要素：触发器可扫、时钟可旁路、复位可控、无 latch/LSSD 例外。
